### Changed

- **The `application-sdk` row is audited** (#461). `docs/application-sdk/engineering.md`'s Row status names each requirement's code and its tests by name, re-checked against `main`: 12 done, 6 partial (onboarding by profile, one application per image, the runner as sole caller, the released hook set, applications on every architecture, a reproducible application image), and six remaining slices, two of them another project's or the owner's.
- **One application, one caller, and a reproducible application image** (#461, slices 3 and 4). `make app-link-check` (in `host-test`) fails when a second application links beside the first, or when a file of `src/` other than `src/core/app_runner.c` calls a hook; `make app-link-check-selftest` (in `security`) proves it names a planted caller; `make reproducible-check APP_DIR=<dir>` builds the application's image twice from clean copies (`scripts/repro_build.py --app-dir`), and the build stage runs it for the example on the ATmega2560.
- **Applications on Cortex-M and ESP32** (#461, slice 2). `make app-firmware-check BOARD=<b>` fails unless the image holds one of the application's own symbols, and the build stage runs it for `mps2-an505` beside the ATmega2560; `make esp32-build APP_DIR=<dir>` compiles the application into the ESP-IDF image as its own object library, with `APP_FW_CFLAGS` and no `src/`. The ESP32 run needs ESP-IDF, which the CI image does not carry.
- **An ESP32 application keeps its include paths** (#461, Codex review). `make esp32-build APP_DIR=<dir>` removes only the framework's own `-I` flags and board header from `APP_FW_CFLAGS`; an application's `APP_CFLAGS` include paths reach the ESP-IDF component, made absolute.
