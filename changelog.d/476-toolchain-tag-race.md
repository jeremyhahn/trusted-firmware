### Fixed

- **`make docker-build-toolchain` checks the image on the tag it owns** (#476): the `cat /etc/ci-toolchain.txt` check runs on `$(TOOLCHAIN_IMAGE)-$(IMAGE_BUILD_ID)` before that build-id tag is removed, not on the shared class tag `$(TOOLCHAIN_IMAGE)` after it, which another CI leg or a disk prune on the shared runner daemon could remove in between (PR #471's Security job failed at `mk/docker.mk:186`). The docker stub in `scripts/test_docker_tag_stub.sh` now refuses a `run` of the class tag and a `run` of a build-id tag it has already removed, and `scripts/test_docker_tag.py` checks from the recorded calls that the check runs on the build-id tag before its `image rm`, so restoring the old order fails `make scripts-test`. `docker-build-esp32` and `docker-build-optee` run no check, and the tests confirm that neither runs the class tag or a removed tag.
