# Plan: SPEC row rp2350 (#429)

## Objective

The RP2350 on the Raspberry Pi Pico 2 W: the firmware core as a HAL
port, with DICE evidence on the part's OTP and secure boot, enrolled
through go-xkms into go-trusted-platform. The onboarding ADR stays
docs-only (#128) and the AVR gate (#7) is not lifted for it.

One branch (`row/429-rp2350`), one PR. The PR marks the row shipped in
docs/SPEC.md only when the whole acceptance holds.

## Slices, in order

1. Fold the per-item PRs into the row with merge commits, oldest first,
   each with its own host tests passing here:
   - #366 I2C master on I2C0 (GP4/GP5): the RP2350 I2C register-model
     test under test/model/cortex-m.
   - #373 PWM: the PWM register-model test.
   - #380 SAR ADC behind analog read and adc-ref: the ADC model test.
   - #390 tone from a TIMER1 alarm toggling the pin through SIO: the
     tone model test.
   - #393 flash EEPROM on the user sector: the NOR-model EEPROM test.
   Conflicts between the folds (board profile, capability lists, board
   page, Makefile test lists) keep every side's peripheral.
2. docs/SPEC.md: the rp2350 row's text records what is built and
   host-tested (the HAL port's peripherals) and what is not yet run on
   the board. The row stays `future` until slices 3 and 4 land.
3. DICE evidence on the RP2350 OTP: the UDS/CDI seed read from OTP rows
   with the read lock, host-tested over an OTP model.
4. Secure boot: tfw-boot's row on the RP2350 boot ROM's signed-image
   path, and enrollment through go-xkms into go-trusted-platform.

## Tests per slice

- Slice 1: each fold's unit tests (`make` host test targets for the
  rp2350 HAL) and the firmware build matrix for the pico2w board.
- Slices 3 and 4 add OTP-model and boot-path host tests; the enrollment
  path adds its integration target.

## Out of scope

- Running anything on the physical board (bench lanes do that).
- Lifting the AVR gate (#7) or changing the onboarding ADR (#128).
- The other HAL ports' rows.
