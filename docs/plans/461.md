# 461: audit of SPEC row application-sdk

Objective: turn the `application-sdk` row (docs/SPEC.md line 56, "in
progress") into either a list of remaining slices or a recorded "done" claim
the owner can act on (DS-9119, DS-5337).

## Slice 1 (this lane): the audit

- `docs/application-sdk/engineering.md`, Row status: one line per requirement
  of the SPEC row and of engineering.md (status done / partial / not
  started, the code, the test by file and test name), every reference
  checked against main; test names replace line numbers, which had drifted.
- Below it, a numbered "Remaining slices" list, one sentence each, with the
  files it would touch and the test that would prove it, and whether it needs
  hardware, another project or an owner decision.
- `changelog.d/461-application-sdk-audit.md`: one line.

Tests added: none. The lane is reading only; no code, test, SPEC or CI file
changes.

## Slice 2: applications on every architecture

- `mk/app.mk`: `app-firmware-check` builds with `esp32-build` on an ESP32
  board, and then fails unless the image holds one of the application's own
  symbols (`nm` of the ELF; ESP-IDF's map file on an ESP32).
- `mk/stages.mk`: the build stage runs it for `mps2-an505` beside the
  ATmega2560.
- `mk/arch/esp32-targets.mk` and the component's `CMakeLists.txt`: the
  application is its own object library, with `APP_FW_CFLAGS`, no `src/`.
- Open: the ESP32 run (`BOARD=esp32-qemu`) needs ESP-IDF, in neither the lane
  image nor CI's, so it is not in the build stage.

## Slice 3: one application, one caller

- `mk/app.mk`: `app-link-check` links the example beside
  `test/mock/app_mock.c` (relocatable link, so only a duplicate hook can fail
  it) and expects a multiple definition of a `tfw_app_` hook; and fails when
  a file in `src/` but `src/core/app_runner.c` names the descriptor or calls
  a hook. Run by `host-test`.
- `app-link-check-selftest`: a copy of `src/` with a call planted in
  `main.c`; the gate must fail and name it. Run by `security`, beside
  `app-header-check-selftest`, from `mk/app.mk` as that one is.

## Slice 4: reproducible application image

- `scripts/repro_build.py --app-dir DIR`: an application inside the source
  tree is taken from each clean copy, one outside it by absolute path; both
  builds get `APP_DIR`. `scripts/test_repro_build.py` covers both cases.
- `mk/firmware.mk`: `reproducible-check` passes `APP_DIR` when set;
  `mk/stages.mk`'s build stage runs it with `APP_DIR=test/app/example`.

## Codex round 3: an ESP32 application relying on OTA

- `tfw_update_slots()` (src/core/update_request.h) replaces the session
  question in `descriptor_ok()`; `hal_ota.c` answers 2 under `TFW_ARCH_OTA`;
  ESP32 board profiles set `TFW_OTA_SLOTS 2u`.
- Test: `test/unit/test_esp_app_ota.c`, the ESP32 link on host.
- Open: the ESP32 build itself needs ESP-IDF, not in the image.

## Codex round 4: no arch conditional in core; CI links an ESP32 app

- `update_request_arch.c` (ARCH_UPDATE_REQUEST := arch) leaves the slots to
  `hal_ota.c`; the core files lose `#if TFW_ARCH_OTA` (lint-conditionals).

## Codex round 5

  not the map; `app-firmware-check-selftest` proves a discarded app fails.
- The automatic example build in `esp32-build` is withdrawn (unspecified scope);
  CI linking an ESP32 application waits for a brief that names it.
