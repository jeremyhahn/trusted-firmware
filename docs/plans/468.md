# #468: the devcontainer toolchain image carries gh

## Objective

Lanes call the forge (GitHub) through `gh`, and node-prep runs `gh --version`
in each image and refuses one without it (DS-9142). The devcontainer toolchain
image gains `gh` v2.103.3, pinned and checked like trivy.

## Slices

1. `scripts/tool-pins.sh` pins `GH_VERSION` and `GH_SHA256` (linux_amd64
   release archive); the Dockerfile `tools` stage downloads the archive,
   checks it with `sha256sum -c`, and unpacks `bin/gh` into `/out`, which the
   `toolchain` stage copies to `/usr/local/bin`. Changelog fragment.
   Check: `make toolchain-hash` moves; with docker,
   `make docker-build-toolchain` and `docker run --rm --entrypoint gh <image>
   --version` prints 2.103.3 (the coordinator builds it where the lane has no
   docker).

## Out of scope

- `.github/` workflows and `docs/SPEC.md`.
- An arm64 `gh` pin: the tools stage refuses a non-amd64 build, as trivy does
  for an unpinned arch, until an arm64 digest is pinned.
