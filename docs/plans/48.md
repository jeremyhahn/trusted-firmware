# Plan: #48, ESP32-P4 HIL (flash, layer-0 boot check, wire over Ethernet)

Ruling 625 (1): flash our build on the ESP32-P4 bench board, run the layer-0
boot check and the wire protocol over Ethernet, and burn **no** eFuse. Every
eFuse burn, secure boot and flash encryption stay owner decisions
([`../multi-arch/esp32-p4-design.md`](../multi-arch/esp32-p4-design.md) §4).

## Slices, in order

1. **Re-read.** `esptool chip-id`, `flash-id`, `espefuse summary` kept
   outside the tree as the before state; the security rows compared with the
   factory record in `docs/development/bench/esp32-p4.md`. Test: every row
   unchanged, or the lane stops before a write.
2. **Build and flash.** `make esp32-build BOARD=esp32p4-poe CRYPTO=none`
   with `boards/esp32p4-poe/sdkconfig.hil0` (and the bench's static-address
   overlay when one is handed to the lane), then HIL-0 step 3: one
   erase-region, four `write-flash` images. Test: `Hash of data verified.`
   after each image.
3. **Layer-0 boot check.** UART0 console after one reset. Test: the
   `tfw-l0: app at 0x20000 verified` line and the app's version equal to the
   branch's.
4. **Wire over Ethernet.** `wirecheck -addr <board>:21574 -board 0x80
   -tier 0` from the lane. Test: `wirecheck: ok`. Needs the board's address
   on the bench network; without one the step stops and the bench doc and PR
   say which input is missing.
5. **No eFuse moved.** `espefuse summary` again; the diff with slice 1's
   output must be empty.

Each slice's commands and results go in the bench doc's "Runs" section.

## Out of scope

- Any `espefuse burn-*`, `--encrypt`, secure-boot or flash-encryption option.
- The restore to the factory image (HIL-0 step 5): the board stays on our
  image, as after the 2026-10-26 run.
- The C6 co-processor, held in reset.
