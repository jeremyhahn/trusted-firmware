# Plan: #48, row `esp32-p4` (the ESP32-P4 PoE board)

## Objective

The ESP32-P4 PoE board runs this firmware on silicon: layer 0 checks trailer
v1 at every boot, the app answers the wire protocol over its IP101 Ethernet,
and the security eFuses are provisioned only on the owner's decisions
(ruling 625 (1): flash our build, run the layer-0 boot check and the wire
protocol over Ethernet, burn **no** eFuse).

## Done

1. Board profile, partition table and the ESP-IDF port (`boards/esp32p4-poe/`,
   `src/hal/esp32/`, `boot/hal/esp32/`), with host tests and the QEMU board
   (`make esp32-qemu-test`). On main.
2. The EEPROM HAL on the host (`test_esp_hal_eeprom`). On main.
3. Bench HIL-0 (`docs/development/bench/esp32-p4.md`): read-only record before
   any write, the `sdkconfig.hil0` build, the four images and the four data
   sectors, the boot log (layer 0 `verified`, the app started), the eFuse
   summary unchanged after. Branch `row/48-esp32-p4`, PR #442.
4. HIL-0 again with this row's own image (branch `row/48-esp32-p4-hil`, PR
   #448): re-read, build, the four writes, layer 0 `verified` with the app
   version of the row's commit, `espefuse summary` before and after with an
   empty diff.
5. **The wire over Ethernet** (same branch, bench page "Row 48: the wire over
   Ethernet on VLAN 101, 2026-11-14"): a static-address overlay, the IP101
   link up at that address, `wirecheck -board 0x80 -tier 0` passed over
   tcp/21574 (PING, CAPS, SYS_INFO, ATTEST refused on the none tier), no
   eFuse line changed.
6. **Slice 1, partial: the pin peripherals and the C6 on silicon**
   (DS-8870, branch `row/48-esp32-p4-selfcheck`, PR #614): a console
   self-check behind `CONFIG_TFW_PERIPH_SELFCHECK` (off by default) in
   `src/hal/esp32/hal_selfcheck.c`, run from `hal_sys.c` after a good board
   init. Done on the board (bench page "Row 48: the HAL peripherals with no
   external wiring, 2026-11-15", every check run PASS, eFuse summary
   unchanged): GPIO, ADC, PWM, tone, pulse, the 16-byte EEPROM check and the
   C6 enable at its pad. It closes the C6 line's "Left" cell. Host tests
   `test_esp_selfcheck` and `test_esp_sys`. Slice 1 stays open (clause 1).

## Open clauses, in order

1. **Slice 1's rest** (Codex P1 on PR #614, ruling 997: "Slice 1 is marked
   complete while its required bus check remains unimplemented"). Fix: every
   doc marks the slice partial; `hal_bus.c` stays in it. Left, as in the
   HAL-port line's "Left" cell:
   1. the `hal_bus.c` self-check on the board: its no-device bus lines
      (I2C probe of an empty address, NACK; SPI two-byte transfer, no
      peripheral selected; 1-Wire reset on a free pin, no presence) are
      pinned on the host only by `test_esp_selfcheck`; a check against a
      device needs one wired to the header;
   2. the bench re-run of the whole-sector EEPROM save and restore, pinned on
      the host only, held for the owner (bench writes; TA 1040, queue 174).
2. **HIL-1: burn the UDS** into the `HMAC_UP` key block. Owner decision.
3. **HIL-2: the secure-boot key digest.** Owner decision.
4. **HIL-3: flash encryption**, release or development mode. Owner decision.
5. **HIL-4: advancing the eFuse floor** (`SECURE_VERSION`). Owner decision.
6. **Item 76:** the go-xkms change it needs, in go-xkms first.

Each HIL step records the eFuse summary before and after on the bench page;
an eFuse cannot be put back, so none runs without the owner's written
decision.

## Out of scope

- The C6 coprocessor's radio (held in reset, never enabled).
- `docs/SPEC.md`'s status cell: it changes when every clause above is met.
