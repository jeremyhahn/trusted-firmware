# 482: MPU-only isolation on the M7 (mps2-an500)

## Objective

docs/cortex-m/engineering.md, Remaining slices item 1 (ruling 632 item 208 a,
#15 option (c)): on the ARMv7-M M7 profile, with no TrustZone, the PMSAv7 MPU
gives three guards:

- a null guard: 32 bytes at address 0, no access, execute-never;
- a stack guard: 1 KiB at the bottom of the stack (the first 1 KiB
  boundary at or above `__heap_start`), no access; it holds because every
  Cortex-M build refuses a frame over 512 bytes, a VLA and `alloca`
  (`-Werror=frame-larger-than=512`, compile and LTO link), so no frame
  steps over the guard (Codex P1 on #497);
- tfw-boot hidden: tfw-boot's flash region (TFW_BOOT_REGION_BASE/SIZE), no
  access for the application.

A MemManage fault escalates to HardFault (SHCSR.MEMFAULTENA stays clear) and
ends in the existing `tfw_cm_fault` PANIC path.

## Slices, in order

1. src/hal/cortex-m/hal_mpu.h and hal_mpu.c: the pure region table
   (`tfw_cm_mpu_regions`) and `tfw_cm_mpu_arm`; the MPU registers in
   cm_regs.h. Test: test/unit/test_cm_mpu.c (bases, sizes, attributes,
   alignment; tfw-boot's table versus the application's), run by
   `make host-test`.
2. Arm it: tfw_cm_reset in src/hal/cortex-m/hal_early.c, and tfw-boot's
   jump in boot/hal/cortex-m/boot_hal_cortex-m.c, gated on TFW_CM_MPU, which
   only boards/mps2-an500 sets. hal_mpu.c joins tfw-boot's objects through
   mk/arch/cortex-m.mk's ARCH_BOOT_SRCS (AVR has no hal_mpu.c).
   Test: `make firmware` and `make bootloader` for every board in
   mk/arch/cortex-m-targets.mk.
3. QEMU wire row: sdk/go/cmd/tfwctl/mpu_qemu_test.go, TestQEMUMPUNullRead,
   a null read through the gdbstub ends in PANIC with the fault PC at the
   read; added to test/integration/cortex-m/qemu_wire_test.sh for
   mps2-an500. Test: `make integration-test-cortex-m-wire`.
4. docs/cortex-m/engineering.md item 1 Done with the test names;
   changelog.d/482-cm-mpu.md.
5. Codex fixes on #497: the AVR boot source list; the frame bound
   (mk/arch/cortex-m.mk CM_FRAME_CFLAGS, hal_mpu.h TFW_CM_FRAME_MAX, a
   1 KiB guard). Test: `make cm-frame-bound-check` (run by
   `bootloader-check`) links a 256-byte frame and refuses a 520-byte, a
   2048-byte and a VLA frame; `make bootloader BOARD=atmega328p`.

## Out of scope

- The ARMv8-M MPU on mps2-an505 (M33) and other boards.
- Unprivileged threads, per-task regions, SHCSR MemManage enabling.
- docs/SPEC.md and .github; any fuse, lock, OTP or lifecycle write.
