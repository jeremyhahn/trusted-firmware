# Plan: #483, TF-M on the M33, measured (cortex-m remaining slice 2)

## Objective

`docs/cortex-m/adr-trust-model-vs-tf-m.md` sizes option (b1), TF-M Profile
Medium with BL2, on an estimate ("on the order of 100 KB of flash and tens of
KB of RAM"; follow-up F1). Replace that estimate with figures measured from a
real build of TF-M v2.3.1 for the STM32H573I-DK, so the owner's open questions
rest on facts. This is fact-finding only: the DICE attestation partition, and
every decision in the ADR, stay the owner's (ruling 746: work ahead, no
hardware).

## Slices, in order

1. **This plan.**
2. **`scripts/tfm-measure.sh`.** Fetches TF-M v2.3.1 at its release tag,
   checks the tag resolves to the pinned commit, and builds, out of tree in a
   work directory outside the repository:
   - the secure side: Profile Medium, BL2 (MCUboot), platform
     `stm/stm32h573i_dk`, once as shipped and once with tf-m-extras'
     example partition as the stub Application RoT partition (one IPC
     service, no crypto of its own; fetched at the commit v2.3.1 pins, so
     the script writes no partition source); the difference is the stub;
   - the non-secure stub: tf-m-extras' example NS application, built
     against the exported `api_ns`.
   It prints the toolchain and CMake versions, the TF-M commit, and the
   `arm-none-eabi-size` figures (text, data, bss; flash = text + data,
   RAM = data + bss) of BL2, the secure image, the stub partition and the
   non-secure stub. It fails if the stub build is no larger than base.
   Test: the script runs to the end on a build host; `bash -n` and shellcheck
   (run by hand; CI's shellcheck covers workflows only) keep it well-formed.
3. **The ADR.** Each estimate for (b1) ("Code size", the Comparison row, F1)
   shows the measured figure, with the TF-M commit, the toolchain, the
   command and the script's output quoted. Decisions and open questions are
   unchanged; where a figure answers part of one, the text says so.
   `changelog.d/483-tfm-measure.md`.

## Out of scope

- The DICE attestation partition itself (open questions 2–13).
- Options (a) and (c) sizes: they have no build to measure; their estimates
  stay marked as estimates.
- QEMU `mps2-an505` (no TF-M platform; open question 11), running on the board.
- `docs/SPEC.md`, `.github`, vendoring any TF-M source into the repository.
- If v2.3.1 had no STM32H573I-DK platform, the nearest STM32H5 platform would
  be measured and named instead.
