# Plan: #490, a test that make bootloader refuses BOOT_OTA=1 BOOT_STORE=1 on the 2560

## Objective

docs/ota/engineering.md (PR #489), Remaining slices item 6: the rule "one
update path per image" was listed as having no test, so a profile change could
build a 2560 image with both the OTA stager in tfw-boot and the store row.

## Finding (slice 1)

The test already exists on main at 9e398aaa: `scripts/test_boot_onepath.py`
(#52 slice 7; last changed in #310), run by `make scripts-test` (mk/stages.mk,
`unittest discover -s scripts -p 'test_*.py'`). It runs `make bootloader` and
`make boot-flash` with `BOARD=atmega2560 BOOT_OTA=1 BOOT_STORE=1` on the
element and soft tiers and asserts a nonzero exit, the refusal text from
mk/boot.mk ("is two update paths, and an image takes one"), both choices, and
that the refusal is the only line make prints. It also pins that
`bootloader-candidate` can still measure the row and that each application
image links one update path (OTA_STAGE=1: store; OTA_STAGE=0: boot session).

Checked in this lane:

- against main's mk/: 5 tests, OK;
- with the `ifeq ($(BOOT_OTA)$(BOOT_STORE),11)` refusal in mk/boot.mk
  disabled: 4 of 5 fail; mk/boot.mk restored.

So no new script is added: a second `test_bootloader_one_path.py` would
duplicate `test_boot_onepath.py` assertion for assertion.
