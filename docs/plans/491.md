# 491: name the OTA_AUTH operator-session and shed-before-verification tests

## Objective

docs/ota/engineering.md's requirement audit (PR #489, on the branch
`row/479-ota-audit`) leaves rows 28 and 37 with no named test (its Remaining
slices item 7). This row adds one named test for each, so the audit can mark
both done. No hardware, no change to `src/`, `boot/`, `mk/` or docs/SPEC.md.

- Row 28: the element tier keeps its operator session (`tfw_auth_gate`) and
  adds the `OTA_AUTH` check (`src/core/ota_activate.c`, `src/core/ota_auth.c`):
  either alone does not activate.
- Row 37: the ATmega2560's store and soft rows shed OTA, never verification
  (item 79, CA m467): the guard is `BOOT_SUPPORTED` in `mk/boot.mk`.

## Slices, in order

1. This plan.
2. Row 37: `test/unit/boot/test_boot_rows_2560.c`, built by the
   `test/unit/boot/test_*.c` wildcard with one registration rule that hands the
   test `BOOT_SUPPORTED` as a string. Cases: every 2560 row verifies with its
   P-256 verifier; every 2560 soft row and store row has `BOOT_OTA=0`; the soft
   row is still a row.
3. Row 28: a case beside `test_activate_and_confirm_need_ota_auth` in the
   suite that links `tfw_otactl_cmd_activate` with the session gate: a held
   `OTA_AUTH` without a session is refused, a session without `OTA_AUTH` is
   refused, both together activate.
4. changelog.d/491-ota-auth-tests.md.

Each new case is shown failing once with its guarded check removed (row 37:
a 2560 soft row with OTA, or a row without a verifier, passed as
`BOOT_SUPPORTED` on the make line; row 28: the gate call removed), then
restored.
