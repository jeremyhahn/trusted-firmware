# Plan: OPTIGA Trust M fit table (#509)

Slice 1 of the audit in #506: fill the fit table of
`docs/multi-arch/adr-optiga-trust-m-onboarding.md` so question 5 (which boards
the tier fits) can be answered.

## Objective

Measure the `optiga` rows and their "without" images, the board's first
`BOARD_TIERS` tier on the same row settings, as `make firmware-matrix` builds
them. Then write each one's text+data and data+bss into the fit table, with the
toolchain versions and the commit measured.

Rows measured (from `make firmware-matrix-list`):

- atmega2560: `soft ETH=0` / `optiga ETH=0`, `soft` (ETH=1, W5100) / `optiga ETH=1`
- mps2-an505: `soft I2C=1` / `optiga I2C=1`

## Slices

1. Build those six rows with `make firmware BOARD=<b> CRYPTO=<t> <settings>`,
   the command `make firmware-matrix` runs per row, on an image that has
   avr-gcc and the Arm toolchain. The budget gate (`size-check`) must pass on
   every row. Quote the printed sizes in the commit message.
2. Fill the table's cells, replace the "No size is measured here" paragraph
   with the toolchain versions and the measured commit, and add a changelog
   fragment. Tests: none new; the rows' `size-check` is the gate.
