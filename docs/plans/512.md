# #512: host tests for tfw-boot's nRF54L UART and RRAM halves

Slice 1 of the nRF54L15 requirement audit (#507).

## Objective

`boot/hal/cortex-m/nrf54l/boot_uart.c` and `boot_rram.c` run on the board
only; nothing on the host checks them. Add one host test for each, over the
nRF54L register model (`test/model/nrf54l_model.h`), built and run by
`make host-test` as the RP2350 boot tests are.

## Slices

1. `boot/hal/cortex-m/nrf54l/test/test_boot_nrf54l_uart.c`, rule in
   `mk/boot.mk` beside `test_boot_rp2350_uart`:
   - init leaves the UARTE's INTEN at 0 (tfw-boot polls);
   - every receive and send is one byte (RX.MAXCNT, TX.MAXCNT 1);
   - `tfw_cm_boot_uart_off` stops the armed receive and puts the UARTE and
     the console pins back to their reset values before the jump.
2. `boot/hal/cortex-m/nrf54l/test/test_boot_nrf54l_rram.c`, rule beside it:
   - RRAMC CONFIG.WEN is set at every store and put back after the write;
   - a span that starts below tfw-boot's region end is refused with no store;
   - a controller that never sets READYNEXT fails the write (TFW_ERR_TIMEOUT)
     after the bounded wait, with CONFIG put back.
3. Changelog fragment `changelog.d/512-nrf54l-boot-tests.md`.

## Out of scope

- Any change to the HAL sources, unless a test finds a defect (then a
  separate fix commit).
- The other slices of #507; board runs.
