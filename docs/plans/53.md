# Plan: row 53, T4 firmware -- the TrustFLEX ATECC608C slot map (a1)

Objective: the firmware side of option (a1) in
docs/device-provisioning/adr-trustflex-608c-slot-map.md, approved by owner
ruling 1243 (T3 and T4 as written in docs/device-onboarding/).

## Slices, in order

1. Slot numbers as board-profile data. `TFW_ATECC_SLOT_UDS` (default 1) and
   `TFW_ATECC_SLOT_IMAGE` (default 2) move from atecc.h to `#ifndef` defaults in
   include/tfw/config.h; tfw-boot's verifier reads `TFW_ATECC_SLOT_IMAGE`. The
   atmega328p and atmega2560 profiles (MIKROE-6774 TFLXTLS) state 6 and 15.
   Tests: test_board_328p.c and test_board_2560.c pin 6 and 15; the simavr boot
   harness's element answers Verify for slot 15.
2. `TFW_CMD_PROV_SLOT_LOCK` (0x7D, `[slot][crc LE]`) and
   `TFW_CMD_PROV_CONFIG_READ` (0x7E, `[block]` -> 32 bytes), under
   `TFW_FEATURE_PROVISION`. SlotLock takes only the UDS and image slots, refuses
   a slot already locked with the status PROV_WRITE_PUBKEY uses, and for the
   UDS slot runs one HMAC keyed by the slot (output scrubbed, never sent) before
   the Lock. The soft-UDS backend answers both TFW_ERR_UNSUPPORTED. The model
   answers SlotLock and any config block.
   Tests: test_provision.c, each refusal and each success path.
3. Frame vectors for both requests and replies in testdata/vectors.h, mirrored
   in sdk/go/internal/vectors/vectors.go, checked in test_frame.c.
4. changelog.d entry.

Gate: `make firmware BOARD=atmega328p PROVISION=1` must still fit; if not, the
lane stops and escalates with the measured size.
