# Plan: a failed boot link names its real cause (#530)

## Objective

`mk/boot.mk`'s `$(BOOT_TARGET).elf` recipe says "it does not fit in the boot
section" for every failed link. On #497 an LTO-link
`-Werror=frame-larger-than` error was reported that way, and a lane spent its
budget sizing RAM and flash that were not the cause. A failed boot link must
name the cause ld/gcc actually gave.

## Slices, in order

1. One slice: `scripts/boot_link_report.sh LINK_ERR BOARD`, called from the
   recipe when the link fails, classifies `link.err`:
   - a `region ... overflowed` or `will not fit` line: today's message
     ("... it does not fit in the boot section."), the overflow/overlap/
     undefined-reference lines, then exit 0, and the recipe runs the
     size recovery (`boot-core-size` and the budget text) as before;
   - anything else: "tfw-boot does not link for BOARD:" and link.err's
     error lines (`error:`, `frame-larger-than`, `vla`, `alloca`,
     `overlaps`, `undefined reference`; the whole log if none match), exit
     1, no size recovery. collect2's generic `ld returned 1 exit status`
     names no cause, so it alone never suppresses the whole log (Codex P1
     on #531; fixtures: an overlap then collect2, an odd line then
     collect2).
   Test: `scripts/test_boot_link_report.py` (run by `make scripts-test`)
   with two canned link.err files, an overflow and a frame-larger-than,
   asserting each message and that the second carries no "does not fit".
   Mutation: a classifier that always prints "does not fit" fails the
   frame-larger-than case.

## Out of scope

- Any change to the boot section, budget or the link flags.
- `.github`, `docs/SPEC.md`, `build/`.
