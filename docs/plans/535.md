# Plan: #535, STM32H573I-DK verified on the board

Objective (owner ruling 768): run every row `docs/boards/stm32h573i-dk.md`
marks "built/host-tested, not yet run on the board" on the bench board, record
the evidence, and add a feature matrix covering every `docs/SPEC.md` row that
names the board.

## Safety (CA 583)

No option-byte, RDP, TrustZone, OTP, lock, protection or WRP write; no mass
erase, recover, `-ob` or `-rdu`. The factory record (`make board-record`)
comes first, kept on the node outside the repository. No probe serial, USB
path, host name or address in a tracked file or commit message.

## Slices, in order

1. Tool: `STM32_Programmer_CLI`, else pyOCD in a venv with the
   `stm32h573iikxq` pack (`CM_FLASH_TOOL=pyocd CM_PROBE_TARGET=stm32h573iikxq`).
2. Factory record: `make board-record BOARD=stm32h573i-dk`; check its size is
   the whole flash (2 MiB) and its sha256 file matches.
3. Current main: `make boot-flash` and `make flash`; capture the boot frame on
   the ST-LINK VCOM (USART1, 115200).
4. Feature runs, one row at a time, each recorded with the make target, the
   commit and the image SHA-256:
   - `make hw-test BOARD=stm32h573i-dk`;
   - I2C (I2C4 PB8/PB9): a scan; a bus with no device answers NACK;
   - tfw-boot's flash writes: a slot write through tfw-boot, read back;
   - EEPROM: write/read on the user sector, refused writes on tfw-boot's span;
   - PWM (TIM5, D6/D5); pulse (`PULSE_IN`/`PULSE_CAPTURE`, a jumper only if
     the pins are free, else "needs a jumper"); tone (TIM3, D3);
   - hardware crypto: what caps reports.
5. Docs: each "not yet run" cell becomes "verified on the board 2026-11-17"
   with its evidence, or "fails: <what>"; a "Feature matrix" section, one line
   per SPEC row naming the board: verified / fails / owner-gated.

A row that fails gets a firmware fix in its own commit, with a host test
where one fits, and `make host-test`.

## As run (2026-11-17)

- pyOCD, not STM32CubeProgrammer; its read-back needed a halt first (fixed in
  `mk/arch/cortex-m.mk`, its own commit).
- Main's images leave tfw-boot halted (no platform block, no pinned key), so
  the bench image was provisioned with the QEMU integration's signer,
  `cm_image`, and written by `make boot-flash BOOT_FLASH_HEX=`.
- `make hw-test` cannot run the board (no row list, no pin facts, no reset
  through the VCOM); the rows were driven with `tfwctl`.
- tfw-boot's own flash writes: not runnable, the board's row has no OTA.

## Codex review of #541 (cdx-541)

1. P2: the 64 MHz clock line becomes a timer-ratio result (PWM, tone and the
   SysTick that measures them share HSI), the absolute frequency pending a
   scope or counter. One commit.
2. P1: the ADC row on the kit, A0 to A5 over the VCOM with the image on the
   board: a channel's pin driven high or low through the GPIO commands (the

   firmware exposes them; else a dated "not run" with its issue. One commit.

## Out of scope

TrustZone, ST Secure Manager, factory device certificate (they need option-byte
or provisioning writes: owner, CA 583); `.github`, `docs/SPEC.md`, `build/`;
restoring the record image unless a run leaves the board unbootable.
