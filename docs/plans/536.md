# Plan: row 536, ESP32-P4 PoE on hardware and its feature matrix

## Objective

Every feature of `boards/esp32p4-poe` beyond HIL-0 has a hardware result with
evidence (owner ruling 768, 2026-11-17), and the board page carries a feature
matrix: one line per `docs/SPEC.md` row that names this board, each verified
(date, evidence), failing (what, for an issue) or owner-gated (needs an eFuse
write, CA 583).

## Safety (CA 583)

- No eFuse write: `espefuse summary` only, before and after, compared.
- Every image built with `boards/esp32p4-poe/sdkconfig.hil0`; the build's
  `sdkconfig` checked for `CONFIG_SECURE_BOOT` and
  `CONFIG_SECURE_FLASH_ENC_ENABLED` not set before any flash.
- The C6 stays in reset. Whole-flash read kept outside the tree before the
  first write; restored only if a run leaves the board unbootable.
- No serial, USB path, MAC, host name or address in a tracked file.

## Slices, in order

1. Record: `espefuse summary` and a whole-flash read into the bench record
   directory outside the tree. Toolchain: esptool in a venv, ESP-IDF v5.5.5.
2. Build `make esp32-build BOARD=esp32p4-poe CRYPTO=none` with the HIL-0
   overlay, check the `sdkconfig`, flash, capture the boot frame.
3. `make hw-test BOARD=esp32p4-poe PORT=<port>`: the cross-implementation
   rows over the console. Per feature: GPIO, PWM (LEDC 0-3), ADC (ADC1 0-7),
   tone (GPIO6), I2C (header 7/8; NACK recorded if nothing is fitted), SPI
   (46/47/48), EEPROM (`tfw_eeprom`, refused writes).
4. The wire over Ethernet: `HW_ETH` rows, development VLAN only.
5. OTA: write, trial, confirm, roll back with the 60 s trial deadline.
6. Docs: "Feature matrix" and "What is not met yet" on
   `docs/boards/esp32p4-poe.md`; changelog fragment.

A failing row gets a firmware fix in its own commit, with a host test where
one fits; a fix too large for this lane goes in the report for an issue.

## As built (2026-11-17)

- The P4's wire is a TCP server only, so `make hw-test` over the serial port
  gets no PING. Added `PORT=tcp:<ip:port>` (`internal/peer`, unit-tested),
  the board's row list and its pin facts.
- Issues to file (the coordinator): (1) PWM and PIN rows hard-code AVR pin 9;
  (2) no hw-test row for TONE; (3) none-tier facts for the CAPS, EEPROM
  reserved-read, I2C_CONFIG and ATTEST-unprovisioned rows; (4) the boot-event
  row on a `tcp:` port; (5) the CLI CAPS row hangs on a `tcp:` port;
  (6) the `HW_ETH` board-dials rows need a host on the development VLAN;
  (7) OTA on the P4 needs a soft- or element-tier image with an operator key.

## Tests

No new host test unless a firmware fix needs one. The evidence is the
hardware runs: command, commit, image SHA-256, result, in the board page.

## Out of scope
