# Plan: #537, the i.MX 95 Cortex-M7 board page (ruling 771)

## Objective

Give the FRDM-IMX95-PRO's Cortex-M7 a board page under `docs/boards/`, in the
shape of `stm32h573i-dk.md`, that records owner ruling 771 (2026-11-17): who
owns which core and which secure world on the i.MX 95, and a feature matrix of
every SPEC row, with its status on this board. Hardware work on the board is queued
after the STM32H573I-DK (#535) and the ESP32-P4 (#536), by ruling 768.

## Slices, in order

1. **This plan.** `docs/plans/537.md`.
2. **The board page.** `docs/boards/frdm-imx95-m7.md`: Who owns what (ruling
   771), The board, The port, tfw-boot, Security facilities, Feature matrix,
   What this page bears on, What is not verified. Every fact cited to
   `docs/multi-arch/imx95-design.md` or `boards/frdm-imx95-m7/`; anything
   else is marked "to confirm against IMX95RM".
3. **The cross-links.** A "Ruling 771" paragraph in
   `docs/multi-arch/imx95-design.md`; the registry's `0x41` line links the
   page; a fragment in `changelog.d/` (the repository's Unreleased entries go
   there, `CHANGELOG.md` says so).
4. **Up to main (ruling 951 (4)).** A signed merge of main, no rebase; then
   the matrix carries every row of the current SPEC table once, with its SPEC
   status and why a row is not this board's, and the device-capabilities
   evidence follows the PWM, ADC, I²C, tone and pulse work main has landed.

Tests: none in code; the change is documentation only. The checks are the
repository's: the releasability patterns (`scripts/releasability.sh`) and
relative links that resolve. The repository has no `make docs-check`.

## Out of scope

- No edit to `docs/SPEC.md` or `.github/`, and no code change.
- No hardware run: every matrix status is "not run".
- The Cortex-A secure world (TF-A, OP-TEE) is not this project's code.

## Proposed SPEC wording, for the owner

The `imx95` row does not say who owns the Cortex-A side. Proposed sentence, to
append to the row's Requirements cell (owner ruling 771, 2026-11-17):

> The Cortex-A55 secure world is upstream Arm Trusted Firmware-A and OP-TEE
> from NXP's BSP, not code of this project; go-trusted-platform and go-xkms run
> in Linux and reach TrustZone through OP-TEE (the firmware TPM TA through
> the kernel's TPM resource-manager device, the PKCS#11 TA through go-xkms's
> PKCS#11 backend, the kernel's TEE device for any custom TA). The M33 System Manager stays NXP firmware and the
> EdgeLock Enclave is the hardware root; this project's product on the i.MX 95
> is the M7 firmware (owner ruling 771).

## Open for the owner

  ref ADR decision 1) is still open; the page follows ruling 771's brief and
  the build (`CPU := cortex-m7`), ARMv7E-M with no TrustZone-M.
