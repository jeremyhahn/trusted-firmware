# #539: ESP32-P4 Ethernet DHCP lease and tfw-wire over TCP in the feature matrix

## Objective

Ruling 768: every built-not-run row on the ESP32-P4 carries a dated hardware
result. The Ethernet link is in the matrix of `docs/boards/esp32p4-poe.md`;
the DHCP lease and tfw-wire over TCP from the bench host have no row of their
own. Add both, each with a dated pass or a dated failure naming its cause.

## Slices

1. This plan.
2. The two rows, run on the board as flashed (no flash write):
   - **Ethernet DHCP lease**: the lease line on the USB console (read only,
     no reset, no serial break), and the board answering `ping` from the
     bench host at the leased address.
   - **tfw-wire over TCP**: `make hw-test BOARD=esp32p4-poe
     PORT=tcp:<board>:21574 HW_TEST_RUN='^TestFirmwareCaps$'` passes
     (the brief's `HW_TEST_RUN='CAPS'` matches no test: `no tests to run`).
   Rows go in the matrix with the date and the evidence; a changelog.d entry.

3. Slice 2, boot console: capture 30 s of the USB console across an RTS/DTR
   reset (no break, no flash write); a lease line passes, a static line reads
   "static overlay"; then `TestFirmwareCaps` over TCP. Result 2026-11-17: no
   lease line; the got-IP gateway is the overlay's placeholder.

4. Slice 3, image without the static overlay (ruling 768 wants the lease):
   ESP-IDF v5.5.5 outside the clone; `make esp32-build BOARD=esp32p4-poe
   ESP_SDKCONFIG_EXTRA=boards/esp32p4-poe/sdkconfig.hil0` (no static IP);
   save the running app slot, write the new app at the app offset only;
   capture the boot console; `TestFirmwareCaps` over TCP.
   If the board's bootloader or layer-0 check refuses the new app (the build
   makes its own image key), write the saved app image back and record the
   cause as the row's dated failure.
   Result 2026-11-17: refused. The bootloader's trailer gate fails the
   signature check (status 14) on both slots and resets in a loop; the saved
   app was written back, boots, and `TestFirmwareCaps` passes over TCP. The
   lease needs the bench's layer-0 image key in the build, or a bootloader
   write, which this slice does not authorise.

5. Slice 4, Codex P1s on PR #568, one commit each, tests first:
   - peer.go: a wrapped TCP wire keeps its read deadline and waits for no
     BOOT (cherry-picked from #547's branch, with #551's meddler fix and its
     test: a partial frame survives the read timeout the deadline makes
     reachable). Tests: a silent TCP peer, a split CAPS response.
   - e2e_rows_test.go: a `partResets` image part (Start resets the board);
     the BOOT-event row needs it, so the P4 over TCP does not select it, and
     TestFirmwareSys checks error counters against a baseline read at start,
     not zero. Test: the P4's list lacks the BOOT row; the AVR lists keep it.
5. Codex P1 at 75e29309: #558's 009425178 cherry-picked (P4 tier/ATTEST/LED rows).
6. Codex P1 at 13f4f765: Sys wants a fixed reset cause only where Start resets.
7. Codex P1 at 2a093a9f: the tone row holds 5% only on a timestamped capture
   (P4); the AVR's counts polling loops. #561 carries the same fix (5a0f0ad5).
8. Codex P1 at 3fe4c014 (`esp_image_test.go:44`): #567's ee76c5eb cherry-picked;
   the esp32-qemu stage image takes its machine's chip id (`ESP_TARGET` via
   `TFW_HW_ESP_TARGET`, esp32c3 when unset). Test: both machines, ids written out.
9. Codex P1 at c09ee101 (`esp32p4-poe.md:117`): I2C and SPI rows say what the
   rows check (the reserved-address refusal; SPI configuration only), with the
   bus transfers, I2C NACK included, not verified (SPI wiring #569). Docs only.
10. Codex P1 at ab9df872 (`peer.go:230`): the firmware reads the current host's
   EOF before it weighs a pending connection, so a row's reconnect after the
   last row's hangup is taken, not refused (`hal_uart.c` `tfw_hal_uart_rx`).
   Test: old hangup and new connection pending before one poll. #567 picks it.

## Out of scope

- Any flash write (if one is needed: app partition only), eFuse writes,
  whole-chip erase.
- The board-dials rows (`HW_ETH`), which need the host on the dev VLAN.
- Recording the address, MAC, host names or device paths in the tree: the
  file says `PORT=tcp:<board>:21574` and "MAC recorded in the bench record".
