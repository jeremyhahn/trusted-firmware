# #539: ESP32-P4 Ethernet DHCP lease and tfw-wire over TCP in the feature matrix

## Objective

Ruling 768: every built-not-run row on the ESP32-P4 carries a dated hardware
result. The Ethernet link is in the matrix of `docs/boards/esp32p4-poe.md`;
the DHCP lease and tfw-wire over TCP from the bench host have no row of their
own. Add both, each with a dated pass or a dated failure naming its cause.

11. #583, the BOOT-event row over TCP (STM32H573I-DK, ESP32-P4): a TCP connect
   does not reset the board as a serial DTR open does. `peer.Target`'s
   `ResetsOnOpen` names the transport's capability; `HW_RESET=cmd:<command>`
   (`TFW_HW_RESET`) is a TCP board's reset hook. `peer.StartBooted` is Start
   for a serial board or the simulator; over TCP it runs the hook, redials
   until the board's server is back and waits for its first bytes, or skips
   the row with "transport does not reset on open" when no hook is set. The
   row is in every board's run again (`partResets` goes): it decides itself.
   Tests: serial, TCP with a hook, TCP without one; the hook's parse and
   failures; the P4's run lists the row.
13. **StartBooted's wire keeps deadlines, and BOOT reaches the first client
   (Codex P1 x2).** The `started` wrapper forwards SetReadDeadline and
   SetDeadline, so a board that sends then stalls fails its read by the
   Device's deadline. The ESP32 TCP HAL holds what the firmware writes before
   the first host connects in a bounded buffer (first bytes kept, the rest
   counted dropped, no heap) and sends it on the first accept only, so the
   BOOT sent before the first poll arrives and a later host is not sent it.
   Tests: a stalled fake peer's read times out; in test_esp_uart_mutate, the
   startup buffer, its send on accept, its overflow and a second host.
14. Codex P1 on #568: after a tcp: reset, openReset reads past the floorConn's
   200 ms per-read timeout until its own deadline (the ESP32-P4 accepts
   before its init ends), and ErrSilent names the time actually waited.
   Tests: BOOT 500 ms after the accept starts; no BOOT is ErrSilent only
   after the whole bound.

   Image SHA-256 (sealed app): `70ae35bd…a5692f`, built from `67155061`.

## Out of scope

- eFuse writes, whole-chip erase; flash writes beyond the app (slices 3/4) or
  step 3's four images and data-sector erase (slice 15).
- The board-dials rows (`HW_ETH`), which need the host on the dev VLAN.
- Recording the address, MAC, host names or device paths in the tree: the
  file says `PORT=tcp:<board>:21574` and "MAC recorded in the bench record".
