# #542: tfw-boot names its refusal when no platform block is provisioned

## Objective

The STM32H573I-DK bench run (#535) booted tfw-boot with no platform block,
and the console showed nothing. The board refused, as it must: with no block
there is no pinned key, so nothing can be verified and nothing may run. But a
board that refuses must say why. On Cortex-M tfw-boot is built without OTA in
the boot section (the soft row), so its recovery is
`boot/hal/cortex-m/recovery_halt.c`, which masks interrupts and sleeps
without a word. The OTA build's recovery (`boot/recovery/recovery_ota.c`)
already announces its reason as an EVENT frame. The halt does not.

The SPEC's provisioning rules do not allow a boot here: no block means no key.
The fix is to name the refusal, not to boot.

## Slices

1. Test (fails before the fix): `test/integration/cortex-m/qemu_test.sh`
   gains an `unprovisioned` row. QEMU loads tfw-boot and the genuine image but
   no platform block, so neither the factory copy nor the home holds one.
   `wirecheck -silent -refusal <status>` passes only if no PING is echoed and
   the device answers with an EVENT that carries the refusal status
   (`TFW_ERR_NOT_PROVISIONED`, a blank block's missing magic). Before the fix the
   halt says nothing, so the row is red.
2. Fix: the Cortex-M halt sends the refusal as an EVENT frame
   (`tfw_frame_encode_event`, the same one recovery_ota.c sends) on entry, and
   sends it again for every whole frame that arrives. A console opened after
   reset, or a host whose first PING is the first thing it sends, still learns
   why. It never answers a command and never boots. `mk/boot.mk` links
   `src/proto/frame.c` into the Cortex-M halt build. The tampered and
   other-key rows keep passing: they get the event, never a PING echo.
   changelog.d entry.

## Out of scope

- `docs/boards/stm32h573i-dk.md` (PR #541 owns it).
- The AVR halt: the 328P's 4 KB section has no room for the frame code, and
  its silence is documented (mk/boot.mk, the 328P row).
- Booting an unprovisioned board, or any change to the provisioning rules.
