# 543: make hw-test rows for the STM32H573I-DK

## Objective

`make hw-test BOARD=stm32h573i-dk PORT=<vcom>` runs the board's rows by name,
with the pin facts #535 measured, instead of by hand.

## Slices

1. Row list and pin facts: `boardImages` and `peerBoards` entries
   for `stm32h573i-dk` (sdk/go/cmd/tfwctl); the PWM row takes each board's
   PWM pin (`pwmPin`) and skips the tick-pin refusal where the tick is SysTick;
   the ADC-pin assertion allows a pin with a port flagged analog only. Test:
   `TestEachAVRBoardRunsTheRowsItsImageServes` gains the board's run and
   not-run rows. `mk/go.mk` hw-test names the board.
2. Codex request-changes on PR #553 (this lane), one commit per finding:
   - P1 startup path (mk/go.mk): DTR on the ST-LINK VCOM resets nothing, so
     every row timed out with ErrSilent on a running board. `TFW_HW_RESET`
     takes `cmd:<probe command>` (internal/peer): purge the receive buffer,
     run the command, wait for the BOOT bytes, as the QMP reset does. hw-test
     defaults it for the board to STM32CubeProgrammer's reset over the
     ST-LINK (`HW_RESET_stm32h573i-dk`), so each row starts from a reset and
     the boot-event and framer-counter rows hold. Tests: FromEnv takes the
     command and refuses an empty one; the command start purges, resets,
     then keeps the first transmission; a failed command is reported.
   - P1 pulse and tone rows (e2e_rows_test.go): `TestFirmwareOneWireAndPulseIn`
     splits into `TestFirmwareOneWire` and `TestFirmwarePulseIn` (pulse
     only); `TestFirmwareTone` new (tone, notone, another pin refused).
     Each board's `pulsePin` and `tonePin` (D3 on the DK, OC2A on the AVRs).
     The board-selection test asserts both run on stm32h573i-dk.
   - P1 analog refusal pin (e2e_firmware_test.go): `TestFirmwareAnalog`
     asked for pin 13, out of range on the DK's 13-pin table, so any error
     passed. It now asks for the board's `ledPin`, a valid pin with no ADC
     channel on every board (`TestFirmwarePin` asserts it). On the AVRs the
     pin stays 13.
   - P1 probe selection (mk/go.mk): the DK's default reset names the
     ST-LINK, `sn=$(CM_PROBE_SERIAL)`, as the cortex-m probe commands do;
     hw-test refuses the default reset with no CM_PROBE_SERIAL, or one
     that is not letters, digits, - and _. Test: scripts/test_hw_test_mk.py
     checks `make -n hw-test` shows `sn=<serial>` and the refusals.
3. Hardware slice (lane hw-553): run the rows on the board with the #535
   image (row/535-stm32h573i-dk-hw, its bench image as the board page's
   "Bench run" builds it), its SHA-256 recorded in the board page's feature
   matrix. The lane container has no STM32CubeProgrammer or stlink tools, so
   the probe is read with pyOCD (`uv tool run pyocd list`), as #535 did, and
   the reset is `TFW_HW_RESET='cmd:pyocd reset -u <serial>'`. Command, one
   row then the whole list: `make hw-test BOARD=stm32h573i-dk PORT=<vcom>
   HW_TEST_RUN='^TestFirmware<Row>$'`. Each row gets a dated verified or
   failed line in the board page's feature matrix; a failure gets an issue.
   Departure, found on the board: its first byte comes about 16 s after the
   reset starts (tfw-boot's software P-256 check at 64 MHz), past the seam's
   5 s StartBound, so every row failed ErrSilent. internal/peer gives the
   board its own bound (`Target.Bound`, 30 s). Test:
   `TestBoundWaitsOutTheDKsSignatureCheck`.
   3b (lane hw-553b): the I2C refusal row on the default (I2C off) image.
   Built from the #535 tip (`make firmware`, `make bootloader-check`, then
   `cm_image` with the board's load addresses, as #535's bench image);
   boot.bin, app.bin and platform.bin packed at 0x08000000, 0x08008000 and
   0x080FE000 give the first 160 KiB SHA-256
   `ce822c89f7c8ea74b1f87b1820f8b9d5b6fd90513426d3e8c9f193946b87d028`.
   Written with `pyocd load` (sector erase only), reset with `pyocd reset`.
   Commands: `make hw-test BOARD=stm32h573i-dk PORT=<vcom> HW_RESET='cmd:pyocd
   reset -t stm32h573iikx -u <probe serial>'
   HW_TEST_RUN='^TestFirmwareRefusesI2CItsCapsLacks$'`, and the same with
   `HW_TEST_RUN='^TestFirmwareAttestRefusedUnprovisioned$'` (#570).
   The board is left on this image.
4. Codex request-changes on PR #553 at 64c92427 (lane cdx-553e), one commit
   per finding, in e2e_rows_test.go:
   - P1 default rows vs this checkout: the `stm32h573i-dk` image is the
     checked-in board_profile.h (four LEDs; GPIO, sched, attest; analog, PWM,
     tone, pulse, EEPROM off), so its default list runs the GPIO rows and
     the analog, PWM, pulse and EEPROM refusal rows. The #535 bench image's
     rows run by name (HW_TEST_RUN), as the I2C=1 image's do. The pin facts
     the GPIO rows use (LED pin 0, PI9; timer pin 1) hold on both tables.
     Test: the board-selection test's run and not-run lists swap.
   - P1 attest refusal: `boardImage.held` names a row the image serves but
     the default list leaves out, with its issue; the DK holds
     `TestFirmwareAttestRefusedUnprovisioned` until #570 settles the image's
     identity state and the row's command timeout. Tests: the DK does not
     run it; every held row is a firmwareRowNeeds row the image serves.
- Merge main (after #541's bench run) into the PR: the board doc's "What is
  not verified" paragraph keeps main's dated bench evidence and this PR's
  hw-test rows. Tests: none new; the branch merges into main cleanly.
5. Codex request-changes on PR #553 at a6135ebb (lane cdx-553f), in
   e2e_rows_test.go: P1 default rows vs enabled peripherals. The merge of
   main brought #535's port into board_profile.h (13-pin table; ANALOG,
   PWM, TONE, PULSE, EEPROM on; I2C off by default; SPI, 1-Wire off), which
   supersedes slice 4's first finding. The `stm32h573i-dk` caps add the five
   features, so the default list runs the Analog, PWM, Tone, PulseIn and
   EEPROM rows and drops their refusal rows; the I2C, SPI and 1-Wire
   refusals stay. Test: the board-selection test's run and not-run lists
   swap for those five features.
6. #581 (ruling 814), Ethernet slice 2 on the DK: hal_eth_mac.c/.h (MAC for
   RMII at the PHY's speed, 4+4 DMA descriptors of 1536 bytes, poll-mode
   tx/rx); lwIP STABLE-2_2_1 vendored under third_party/lwip (core, ipv4,
   netif/ethernet), NO_SYS=1 with DHCP and TCP; hal_eth_netif.c glue behind
   ETH_MAC=1 (ETH=1 is the W5x00 link already; default image unchanged), console `eth: dhcp bound`. Tests:
   test_h5_eth_mac.c over a fake register block (ring wrap, OWN hand-off,
   tail pointers, errors); on the board, a DHCP lease within 30 s, recorded
   in the board doc and feature matrix. tfw-wire over TCP is the next slice.
7. #582 (ruling 814), tfw-wire over TCP on the DK: hal_eth_wire.c is the
   ETH_MAC=1 image's link (in place of link_serial.c): the UART and one TCP
   connection on port 21574 (the ESP32's wire port) feed the one transport,
   a reply goes back on the wire its request came from, events stay on the
   UART; a new connection replaces the one held. hal_eth_wire_tcp.c is the
   lwIP raw-API listener behind it (receive window reopened as the
   transport reads). Tests: test_h5_eth_wire.c over a fake TCP seam (wire
   switching, hold, window reopening, tx batching and flush, a dropped
   peer's reply discarded, replacement); on the board, tfwctl's P4 row set
   with PORT=tcp:<lease>:21574 (PR #568's host transport), each row dated
   in the board doc and feature matrix, a failure with an issue.
8. Coverage (lane cov-553): sdk/go/internal/peer fell to 88.0%, under the
   90% floor (m655), through an earlier merge. Table tests in
   peer_open_test.go cover OpenCmd, OpenQMP, startQMP and startCmd's refusals
   (no port, failed reset, no QMP listener, no purge, failed purge, boot).
   Test code only; the floor is unchanged.
9. #570 follow-up (lane row570b), host only: a per-board attest timeout in
   the hw row facts (`boardImage.attestTimeout`; the DK 45 s from the
   measured 27.7 s, others the suite's 5 s), used by the attest row, with a
   unit test; then `make cortex-m-dk-image BOARD=stm32h573i-dk`, the DK's
   signed bench set with the unprovisioned boot, by cm_image as
   cortex-m-qemu-image signs (which refuses the DK), documented in the
   board doc. Test: the target builds in the lane.
10. Codex round 4 on PR #553 (lane cdx-553r4c), two P1s. (a) A TCP
    connection replaced mid-frame left the shared transport's partial frame
    and owed reply to its successor: the link API gains
    `tfw_link_take_reset()` (1 once after the H5 wire drops or opens while
    TCP is the current wire; 0 on link_serial.c and link_eth.c), and
    tfw_transport_poll aborts the framer and drops the owed reply on it.
    Test: test_h5_wire_transport.c, the real transport and framer over the
    H5 wire: a partial frame on connection A, a full request on B, B is
    answered; a reply owed to A is not sent to B. (b) hal_eth_netif.c: link
    loss stops the MAC and returns to ETH_WAIT_LINK, so autonegotiation is
    awaited and MACCR is set from PSCSR again. Test: the ETH_MAC=1 DK image
    builds.
11. CI fix (lane ci-553u). The DK's RAM_BUDGET is a plain number with an
    ETH_MAC=1 override, the form board-check reads; lint-arch-leak no longer
    takes lwip/ under src/hal/cortex-m/ for ESP-IDF (the port builds lwIP
    itself). Test: test_esp32_port.py's test_cortex_m_lwip_is_its_own.
