# 543: make hw-test rows for the STM32H573I-DK

## Objective

`make hw-test BOARD=stm32h573i-dk PORT=<vcom>` runs the board's rows by name,
with the pin facts #535 measured, instead of by hand.

## Slices

1. Row list and pin facts: `boardImages` and `peerBoards` entries
   for `stm32h573i-dk` (sdk/go/cmd/tfwctl); the PWM row takes each board's
   PWM pin (`pwmPin`) and skips the tick-pin refusal where the tick is SysTick;
   the ADC-pin assertion allows a pin with a port flagged analog only. Test:
   `TestEachAVRBoardRunsTheRowsItsImageServes` gains the board's run and
   not-run rows. `mk/go.mk` hw-test names the board.
2. Codex request-changes on PR #553 (this lane), one commit per finding:
   - P1 startup path (mk/go.mk): DTR on the ST-LINK VCOM resets nothing, so
     every row timed out with ErrSilent on a running board. `TFW_HW_RESET`
     takes `cmd:<probe command>` (internal/peer): purge the receive buffer,
     run the command, wait for the BOOT bytes, as the QMP reset does. hw-test
     defaults it for the board to STM32CubeProgrammer's reset over the
     ST-LINK (`HW_RESET_stm32h573i-dk`), so each row starts from a reset and
     the boot-event and framer-counter rows hold. Tests: FromEnv takes the
     command and refuses an empty one; the command start purges, resets,
     then keeps the first transmission; a failed command is reported.
   - P1 pulse and tone rows (e2e_rows_test.go): `TestFirmwareOneWireAndPulseIn`
     splits into `TestFirmwareOneWire` and `TestFirmwarePulseIn` (pulse
     only); `TestFirmwareTone` new (tone, notone, another pin refused).
     Each board's `pulsePin` and `tonePin` (D3 on the DK, OC2A on the AVRs).
     The board-selection test asserts both run on stm32h573i-dk.
   - P1 analog refusal pin (e2e_firmware_test.go): `TestFirmwareAnalog`
     asked for pin 13, out of range on the DK's 13-pin table, so any error
     passed. It now asks for the board's `ledPin`, a valid pin with no ADC
     channel on every board (`TestFirmwarePin` asserts it). On the AVRs the
     pin stays 13.
   - P1 probe selection (mk/go.mk): the DK's default reset names the
     ST-LINK, `sn=$(CM_PROBE_SERIAL)`, as the cortex-m probe commands do;
     hw-test refuses the default reset with no CM_PROBE_SERIAL, or one
     that is not letters, digits, - and _. Test: scripts/test_hw_test_mk.py
     checks `make -n hw-test` shows `sn=<serial>` and the refusals.
