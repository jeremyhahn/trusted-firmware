# #544: STM32H573I-DK hardware crypto (PKA ECDSA P-256, HASH SHA-256)

## Objective

Give the STM32H573I-DK a hardware tier beside its soft one (ruling 768): SHA-256
on the HASH peripheral and ECDSA P-256 sign/verify on the PKA, behind
`include/tfw/crypto.h`, selected by the board profile. TrustZone, the Secure
Manager and the factory certificate stay owner-gated (CA 583). The keys stay
where the soft tier keeps them, so CAPS still reports `TFW_CRYPTO_SOFTWARE`:
the peripherals speed the arithmetic, they do not protect a key.

**Not confirmed** (RM0481 not read): whether the PKA reaches INITOK with only
the RNG's bus clock on, and the HASH's timing. Each driver polls with a bound;
a peripheral that does not answer makes the provider answer from the soft code
for the rest of the boot, so an unconfirmed fact costs speed, never a result.

## Slices

1. **Plan** (this file).
2. **HASH SHA-256**: `src/crypto/stm32h5/h5_hash.c` (`tfw_h5_hash_sha256`),
   register access through `h5_crypto_regs.h` so the host links a model.
   Test `test/unit/test_h5_hash.c`: a model of the HASH that rebuilds the
   message from DIN and STR.NBLW and digests it with `src/crypto/sha256.c`;
   the FIPS 180-2 vectors (empty, "abc", the 448-bit one, a 1000-byte run and
   every length 0..67), a timeout that reports `TFW_ERR_TIMEOUT`.
3. **PKA ECDSA P-256**: `src/crypto/stm32h5/h5_pka.c` (sign and verify), the
   RAM layout and result codes above. Test: a model that checks the operand
   layout (word order, the two-word terminator, the bit counts) and answers
   the verify with micro-ecc; the soft provider's vectors.
4. **Provider and profile**: `src/crypto/stm32h5/provider.c` wraps the soft
   provider (renamed per object, as the auto tier does) and routes `sha256`,
   `sign`, `verify_operator` and `verify_image` to the drivers, falling back to
   soft on a peripheral that does not answer. `boards/stm32h573i-dk/profile.mk`
   names the tier (`BOARD_TIERS := soft stm32h5`); the soft images unchanged.
5. **Hardware verification** on the kit: the next hardware slice.

## Out of scope

Option bytes, TZEN, RDP, OTP, key storage in the SAES or the PKA, the Secure
Manager, the factory certificate, the AES peripheral, and the RNG as the
tier's entropy source.
