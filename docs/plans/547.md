# #547: Pin and PWM hw-test rows use the board's pin facts

## Objective

TestFirmwarePin and TestFirmwarePWM hard-code pin 9, the AVR's OC1A/OC2B.
On the ESP32-P4 board pin 9 is GPIO22, an ADC input with no LEDC channel,
so the hardware run (#536, PR #546) never measured LEDC PWM. The rows take
the PWM pin from the board's pin facts (`peerBoards`) instead.

## Slices

1. Merge PR #546's branch (esp32p4-poe pin facts and row list), then add
   `pwmPin` to `peerBoard`: 9 on the ATmega328P and ATmega2560 (unchanged),
   0 (GPIO2, LEDC0) on esp32p4-poe. TestFirmwarePin and TestFirmwarePWM
   read it. The esp32p4-poe has no compare unit spent on a tick, so
   `tickPin` becomes optional (-1 = none) and the PWM row skips that
   refusal there; its old value 0 was the LEDC0 pin, which accepts a duty.
   Test: a unit test over the row selection: every board whose row list
   runs the Pin or PWM row has pin facts, its PWM pin is not its no-PWM,
   tick or ADC pin, and the AVR boards keep pin 9.
2. changelog.d entry.
3. Codex review of PR #555 (P1 findings):
   - TCP wire blocks a wrapped row: meddler forwards SetReadDeadline to
     its conn, and openPeer sets no boot wait on a port that does not
     reset the board (`peer.Target.Resets`, false for `tcp:`). Test: a
     host row over a silent TCP listener, wrapped in meddler, must open
     at once and fail a request within its deadline.
   - LED pin (finding 2), none tier (finding 3), TCP reset (finding 4):
     owned by the stacked PRs #565, #559 and #558. Here the esp32p4-poe
     run drops the rows they fix (`boardImage.drop`, each naming its PR)
     instead of duplicating the fixes; each PR takes its rows back.
     Test: the row-selection test asserts the esp32p4-poe run omits them.
     Dropped rows and owners: #559 (none tier) TestFirmwareCaps,
     TestFirmwareEEPROM, TestFirmwareI2CConfig,
     TestFirmwareAttestRefusedUnprovisioned; #558 (fresh boot over tcp:)
     TestFirmwarePingDeliversTheBootEventWithNoBootWait, TestFirmwareSys.
     #565 (LED flag): the Pin row takes the LED pin's flags from the pin
     facts (`ledFlags`), digital only on esp32p4-poe until #565 lands.
   - Merge of main (#567): main serves the none-tier and fresh-boot rows
     itself (`noneTier`, `partTCP`) and the LED flag (`noLED`), so the
     esp32p4-poe drop list and `ledFlags` go; `drop` stays for later rows.

## Out of scope

- The firmware and the board tables (boards/*/board.c).
- The other rows' hard-coded pins (analog 13, 1-Wire 9): separate rows.
