# 551: CLI CAPS row hangs over TCP

## Objective

`TestFirmwareElementWithoutTheCapsBitIsRefusedAsUnsupported` hangs over a
`tcp:` PORT until the 10-minute test timeout (ESP32-P4 run, #536, ruling 768).

Cause: a `tcp:` PORT dials a running board with no reset, so no BOOT event
comes. `tfw.New` waits for BOOT through `fill`, which bounds a read only by
`SetReadDeadline` or a floor the conn keeps for itself (serialport's 200ms).
The row's `meddler` wraps the conn as a plain `io.ReadWriter`, which hides
`SetReadDeadline`, and a bare `net.Conn` has no floor, so `io.ReadFull`
blocks forever.

## Slices

1. Take the `tcp:` PORT from #536 (b53d01eb, cherry-picked) so the peer
   dials TCP on this branch.
2. Test: a silent TCP peer, read through a wrapper that hides the deadline
   the way `meddler` does, must return within a bound
   (`sdk/go/internal/peer`). It fails (hangs, caught by a watchdog) before
   the fix.
3. Fix: the conn `Open` returns for `tcp:` keeps a read floor like
   serialport's: every Read is bounded by the floor or by the caller's own
   deadline, whichever is sooner, and returns the timeout error, which
   `fill` treats as "no bytes yet".

## Out of scope

- The rest of #536's row list and docs (PR #546 lands them).
- Changing `tfw.Device`'s read loop or the `meddler` test helper.
