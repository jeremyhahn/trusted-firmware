# #552: the OTA rows on the ESP32-P4, on a soft-tier image

Objective: the ESP32-P4's OTA SPEC rows (write, trial, confirm, roll back)
run on the board, each with a dated result and its evidence in
`docs/boards/esp32p4-poe.md`'s feature matrix (ruling 768). The bench HIL-0
image is `CRYPTO=none`, which has no operator session, so no OTA row has run.

## Slices, in order

1. Toolchain. ESP-IDF v5.5.5 and esptool / espefuse v5.6.0 installed outside
   the clone (docs/multi-arch/adr-esp-idf-integration.md). The lane image has
   neither, nor Docker, so `make docker-firmware` cannot run here, and its
   `make firmware` is not the ESP32 build anyway (`profile.mk`).
2. Build: `make esp32-build BOARD=esp32p4-poe CRYPTO=soft
   ESP_SDKCONFIG_EXTRA="boards/esp32p4-poe/sdkconfig.hil0 <static-address
   overlay>"`: secure boot and flash encryption stay off, so first boot burns
   no eFuse.
3. Before any write: `espefuse summary` (read only) and `esptool read-flash 0
   ALL` of the whole part, kept outside the tree: the restore image.
4. Flash: `erase-region` of the data partitions only, then `write-flash` of
   the sealed app at `0x20000` and `tfw_plat.bin` at `0x11000`. The build
   generates its own layer-0 image key, so the bootloader at `0x2000` and the
   table at `0x10000` are written with them as in the bench procedure
   (docs/development/bench/esp32-p4.md); never `erase-flash`, never an eFuse.
5. Operator session: the operator key the OTA rows take (`OPERATOR_KEY`)
   provisioned into `tfw_auth` the way the auth rows expect.
6. Run: `make hw-test BOARD=esp32p4-poe PORT=tcp:<board>:21574
   HW_TEST_RUN='OTA' OPERATOR_KEY=<pem>`; a row-side defect in
   `sdk/go/cmd/tfwctl` is fixed with its test (`make sdk-test`).
7. Record: each OTA row's result, date and evidence replaces the matrix's
   `esp32-p4, ota | not run` line; failures named for an issue. Added lines
   carry no address, MAC or device path. `espefuse summary` after; restore
   the read-back image if the board is left unbootable.

## Out of scope

eFuse writes of any kind, secure boot, flash encryption, the UDS identity;
the board-dials Ethernet rows (`HW_ETH`); the other failing matrix rows.
