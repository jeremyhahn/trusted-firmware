# #560: the Pin row expects the LED flag only where the board has an LED

## Objective

On the ESP32-P4 the Pin row reported `pin 11 flags = digital, want digital
and led`. The P4 has no LED on the header (boards/esp32p4-poe/board.c): pin
11 (GPIO32) only stands in for one, so the row failed on a wrong
expectation, not on the firmware. Give each board an LED fact and make the
Pin row expect the led flag only where the board has an LED on that pin.

## Slices, in order

1. LED fact: `hasLED` in `peerBoard` (sdk/go/cmd/tfwctl/e2e_pins_test.go),
   true on atmega328p, atmega2560 and the MPS2 boards, false on
   esp32p4-poe; `ledPinFlags` gives the flags the Pin row expects (digital
   and led, or digital with led absent). Test: a host test that a board
   with an LED expects digital and led, one without expects led absent, and
   the AVR boards keep their led expectation while the P4 has none.
2. The row: `TestFirmwarePin` (e2e_firmware_test.go) checks the descriptor
   against `ledPinFlags` instead of a hard-coded digital and led.

## Out of scope

- Hardware: the P4 run of the Pin row is left to the next P4 hardware lane.
- The firmware's pin table: board.c is right; only the test was wrong.
