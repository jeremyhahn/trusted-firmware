# #570: `TestFirmwareAttestRefusedUnprovisioned` on the STM32H573I-DK

Epic #543, row branch `row/543-h5-hw-rows`.

## Objective

The row gets no reply to `attest` within the suite's 5 s command timeout on
the DK. Find which of two causes it is, fix that side, and record the
measured time.

## What the code says before measuring

- The soft tier counts as provisioned when tfw-boot hands off a usable CDI
  (`tfw_crypto_init`, `src/crypto/soft/provider.c`). tfw-boot derives one
  only from a UDS in its `uds_slot`.
- The bench image's signer (`test/integration/cortex-m/cm_image.c`) patches a
  fresh UDS into `boot.bin`; it also writes `boot-unprovisioned.bin`, the
  same boot with the UDS slot left erased, for exactly this row.
- So the bench image is provisioned: `attest` signs (software P-256 at
  64 MHz) instead of refusing. The row's precondition is wrong for it.

## Measurement plan

1. On the image the board carries, send one `attest` over the console with a
   30 s timeout; record the time to the reply and its status.
2. Rebuild the signed set with the signer, pack `boot-unprovisioned.bin`
   with `app.bin` and the platform block, write it by sector erase
   (`pyocd load -e sector`, target `stm32h573iikxq`), no option byte, RDP,
   TZEN, OTP or WRP write, no mass erase.
3. Run the row alone on that image with `make hw-test`; record the result
   and the time to the refusal.
4. Put the default (provisioned) image back so the other rows keep their
   board.

## Fix, by what the measurement shows

- Refusal on the unprovisioned image within 5 s: the row needs an
  unprovisioned image. Record it in the board doc; keep the row out of the
  provisioned image's list in `sdk/go/cmd/tfwctl/e2e_rows_test.go`, held
  (the held map takes an issue, so #570, the measurement's record) with
  its reason rewritten.
- Refusal slower than 5 s: add a per-board attest timeout in the hw suite's
  board facts, set from the measured time with margin, with a unit test.

## Outcome (2026-11-17)

- Provisioned bench boot: `attest` answered with evidence in 27.7 s, twice,
  against 2.0 s for `caps`: about 26 s of software P-256 at 64 MHz.
- `boot-unprovisioned.bin`: `attest` refused at once ("no provisioned
  identity"); the row passed under `make hw-test`, 16 s from the probe reset
  (the boot).
- So the precondition was the cause. No timeout change: the refusal is
  immediate. The row stays held from the bench boot's list with its reason
  rewritten; the board doc says how to run it.

## Landed (2026-11-20)

The slice (the DK's 45 s `attestTimeout`, `make cortex-m-dk-image`, the
board doc and changelogs) is on main in #584's squash. Left: the row's
board run on `bench-unprovisioned.hex`, a separate device slice.

## Out of scope

Provisioning the board for attestation (owner, CA 583), the signing time of
a provisioned `attest` beyond recording it, and any change to tfw-boot.
