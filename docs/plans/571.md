# 571: a push to main never cancels a main run in progress

Ruling 796 (Tenant Agent, 11:20Z): eight main pushes in a row ended
cancelled and main has no completed CI run, which breaks ruling 742. The
order: "concurrency for push to main uses cancel-in-progress false (main runs
queue and each completes; PRs keep cancel-in-progress true)." The one-line
change, in `.github/workflows/ci.yml`'s concurrency block: `cancel-in-progress:
true` becomes `cancel-in-progress: ${{ !(github.event_name == 'push' &&
github.ref == 'refs/heads/main') }}`. The group expression stays as it is; the
comment above the block drops the Gitea 1.27.1 reason (CI runs on GitHub only,
ruling 688) and states the main and PR behaviour.
