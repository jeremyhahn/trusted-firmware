# Plan #579: STM32H573I-DK Ethernet slice 1, the PHY over MDIO

Objective: identify the kit's Ethernet PHY over the MAC's MDIO and read its
link on the board, as slice 1 of the Ethernet ADR
([`../multi-arch/adr-stm32h5-ethernet.md`](../multi-arch/adr-stm32h5-ethernet.md),
PROPOSED, #540). No MAC data path, DMA or IP stack.

## Slices, in order

1. **Driver and unit test.** `src/hal/cortex-m/stm32h5/hal_eth_mdio.c` and
   `.h`: the SBS RMII select, the ETH MAC/TX/RX clocks, the nine RMII pins on
   AF11 (ST's pin data for the kit), MDC at HCLK/42 (1.52 MHz), MDIO read and
   write through MACMDIOAR/MACMDIODR, a scan of addresses 0-31, PHYID1/PHYID2
   and BMSR read twice (the link bit latches low). `ETH_PROBE=1` (off by
   default) queues `eth: phy addr=N id=XXXX:XXXX link=up|down` on the
   console at boot; the default image is byte-identical.
   Test: `test/unit/test_h5_eth_mdio.c`, the OUI/model/revision decode, the
   BMSR link bit, the scan over a fake MDIO bus (latched-low link, a failed
   read, address 31, an empty bus) and the boot line.
2. **On the board.** The factory record first (`make board-record`), then
   `make boot-flash` and `make flash` of the `ETH_PROBE=1` image, the line
   captured on the Virtual COM port. The board page rows (Ethernet PHY, link)
   and the feature matrix dated with the commit, the image sha256 and the IDs
   read; the ADR's hardware table corrected if the PHY is not a LAN8742A.

## Out of scope

- The MAC's DMA, descriptors, lwIP and DHCP (ADR slice 2); tfw-wire over TCP
  (slice 3). The board's IP stack row stays "none yet".
- Any MAC address or lease in a tracked file.
