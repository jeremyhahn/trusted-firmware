# 590: TrustZone-M secure/non-secure split and NSC veneers (ADR slice a)

Objective: the first CMSE code in the tree. A `TZ=1` build of mps2-an505
(QEMU) and nucleo-h563zi makes two images: a secure image that sets up the
SAU and enters a non-secure image, and a non-secure image that calls the
secure world through one NSC veneer. Ruling 935, docs/multi-arch/
adr-mcu-dice-attestation.md slice (a). `TZ=0` builds are unchanged.

## Memory split (one header per board, the single source of truth)

`src/hal/cortex-m/tz/tz_map_<board>.h` holds every address. The C region
table and both linker scripts (`mk/arch/cortex-m/tz_s.ld`, `tz_ns.ld`, run
through the C preprocessor with that header) read it, so they cannot disagree.

| region       | mps2-an505 (IDAU: bit 28 = Secure) | nucleo-h563zi (RM0481 aliases) |
|--------------|------------------------------------|--------------------------------|
| S code       | 0x10000000, 62 KiB (SSRAM-0 S)     | 0x0C000000, 126 KiB (flash S)  |
| NSC (veneers)| 0x1000F800, 2 KiB, in S code       | 0x0C01F800, 2 KiB, in S code   |
| NS code      | 0x00100000, 64 KiB (SSRAM-0 NS)    | 0x08020000, 256 KiB (flash NS) |
| S RAM        | 0x30000000, 32 KiB (internal SRAM) | 0x30000000, 64 KiB (SRAM1 S)   |
| NS RAM       | 0x00200000, 64 KiB (SSRAM-0 NS)    | 0x20010000, 64 KiB (SRAM1 NS)  |
| NS periph    | 0x40000000-0x4FFFFFFF              | 0x40000000-0x4FFFFFFF          |

SAU regions (32-byte granules): 0 NS code, 1 NS RAM, 2 NS peripherals,
3 NSC. Everything else is Secure. On mps2 the secure start-up also opens
the SSRAM-0 MPC blocks of NS code and NS RAM, the expansion APB PPCs (UART0)
to NS, and sets NSCCFG.CODENSC so the IDAU lets the SAU's NSC region stand.
On the H563 the image needs TZEN=1 and the flash secure watermark over the
first 128 KiB: option bytes the owner sets (CA 583); nothing here writes an
option byte. GTZC MPCBB (SRAM NS blocks) and the H563 console are the
hardware slice's, not this one: the H563 images build and size-check only.

## Build shape

- Secure image: `-mcmse`, linked with `--cmse-implib --out-implib`, giving
  the import library `tz_s_veneers.o` (the `.gnu.sgstubs` in the NSC region).
- Non-secure image: linked against that import library.
- Veneer list, this row: `tfw_s_version` (`include/tfw/tz_s_api.h`), which
  returns the constant `TFW_S_VERSION`.
- Secure start-up (`src/hal/cortex-m/tz/tz_s_main.c`): SoC opening (mps2),
  SAU from the region table, SHCSR.SECUREFAULTENA, VTOR_NS, MSP_NS, then a
  `cmse_nonsecure_call` (BLXNS) to the NS reset handler. Its SecureFault
  handler prints SFSR and SFAR.
- Make (`mk/arch/cortex-m-targets.mk`): `tz-firmware` (both images,
  `tz-size-check`), refused on a board without `TZ_MAP`. `firmware` and
  `size-check` with `TZ=1` run it (one `ifeq` in mk/firmware.mk), so
  `make BOARD=nucleo-h563zi TZ=1 firmware` builds and checks both images.

## Slices, in order, with their tests

1. This plan.
2. Map headers, region table and checker; host unit test
   `test/unit/test_tz_regions.c`, built once per board: bounds, 32-byte
   alignment, NSC inside S code, no overlap, S RAM and S code not NS; and
   the checker refuses mutated tables.
3. Linker scripts, secure start-up, veneer, NS image, make targets;
   `make BOARD=nucleo-h563zi TZ=1 firmware` and the same for mps2-an505.
4. QEMU case `test/integration/cortex-m/qemu_tz_test.sh` (its own script:
   qemu_test.sh boots tfw-boot plus an application, which this case has
   neither of), target `integration-test-cortex-m-tz` beside the wire
   targets: the secure image boots and enters NS; NS prints the veneer's
   value; NS reads S RAM and the secure handler reports SecureFault with
   SFAR at S RAM.

Out of scope: the DICE layer behind the NSC API (slice b), GTZC, the H563
console, flashing, TZEN/RDP/option bytes/OTP, CI workflow changes.
