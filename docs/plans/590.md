# 590: TrustZone-M secure/non-secure split and NSC veneers (ADR slice a)

Objective: the first CMSE code. A `TZ=1` build of mps2-an505 (QEMU) and
nucleo-h563zi makes a secure image that sets up the SAU and enters a
non-secure image, which calls the secure world through one NSC veneer.
Ruling 935, ADR mcu-dice-attestation slice (a). `TZ=0` builds are unchanged.

## Memory split

`src/hal/cortex-m/tz/tz_map_<board>.h` holds every address; the region table
and both linker scripts (`mk/arch/cortex-m/tz_s.ld`, `tz_ns.ld`, run through
the C preprocessor with it) read it, so they cannot disagree.

| region    | mps2-an505 (IDAU bit 28)   | nucleo-h563zi (RM0481)    |
|-----------|----------------------------|---------------------------|
| S code    | 0x10000000 62 KiB SSRAM-0  | 0x0C000000 126 KiB flash  |
| NSC       | 0x1000F800 2 KiB, in S code| 0x0C01F800 2 KiB, in S    |
| NS code   | 0x00100000 64 KiB SSRAM-0  | 0x08020000 256 KiB flash  |
| S RAM     | 0x30000000 32 KiB SRAM     | 0x30000000 64 KiB SRAM1   |
| NS RAM    | 0x00200000 64 KiB SSRAM-0  | 0x20010000 64 KiB SRAM1   |
| NS periph | 0x40000000-0x4FFFFFFF      | 0x40000000-0x4FFFFFFF     |

SAU regions (32-byte granules): NS code, NS RAM, NS peripherals, NSC; the
rest is Secure. On mps2, `tz_soc_mps2.c` also opens the SSRAM-0 MPC blocks of
NS code and RAM, the expansion APB PPCs (UART0), and NSCCFG.CODENSC. The
H563 images need TZEN=1 and the bank 1 secure watermark over 128 KiB, option
bytes the owner sets (CA 583); nothing here writes one. GTZC MPCBB and the
H563 console are the hardware slice's: the H563 images build and size-check.

## Build shape

- Secure image: `-mcmse`, `--cmse-implib --out-implib` writes the import
  library `tz_s_veneers.o`; `.gnu.sgstubs` goes in the NSC region by
  `--section-start` from TZ_NSC_BASE (ld refuses a script-only address).
- Non-secure image: linked against that import library.
- Veneers this row: `tfw_s_version` (`include/tfw/tz_s_api.h`), a constant.
- Secure start-up (`tz_s_main.c`): SoC opening, SAU from the table,
  SecureFault enabled, VTOR_NS, MSP_NS, BLXNS (`cmse_nonsecure_call`) to the
  NS reset handler; the SecureFault handler prints SFSR and SFAR. Both worlds
  print through `tz_console.h` (CMSDK UART0 on mps2, none on the H563).
- Make (`mk/arch/cortex-m-targets.mk`): `tz-firmware` and `tz-size-check`,
  refused without the profile's `TZ_MAP`; `firmware` and `size-check` with
  `TZ=1` run them (one `ifeq` in mk/firmware.mk).

## Slices, with their tests

1. This plan.
2. Maps, region table, checker; `test/unit/test_tz_regions.c` built per
   board (mk/host.mk `test_tz_regions_<board>`, in `make test`): bounds,
   alignment, NSC inside S code, no overlap, nothing Secure made NS, and
   mutated tables refused.
3. Linker scripts, secure start-up, veneer, NS image, make targets:
   `make BOARD=<b> TZ=1 firmware` on both boards.
4. `test/integration/cortex-m/qemu_tz_test.sh`, run by
   `make integration-test-cortex-m-tz`: S enters NS; NS prints the veneer's value; NS reads S RAM, never returns,
   and the secure handler reports a SecureFault with SFSR.AUVIOL (SFAR is
   checked when SFARVALID is set; QEMU 10 leaves it clear).

## Slices a+b joined: the DICE service in the TZ=1 image (ruling 935)

5. Merge row/590-tz-dice-api (590b.md). The four calls' types and
   prototypes move to `include/tfw/tz_s_api.h` with `TFW_NSC`;
   `dice_service.h` keeps init/clear and `TFW_NS_CHECK`.
6. `dice_service.c`, deviceid_p256, alias/uccs/tmpl, sha256 and micro-ecc
   link into `tz_s.elf` only (`--gc-sections` drops alias.c's provider
   mint); the four calls land in `tz_s_veneers.o`. `tz_s_dice_start`
   (tz_veneer.c) inits the service from fixed QEMU test vectors before NS
   runs; the real UDS/CDI hand-off is the tfw-boot slice.
7. `tz_ns_main.c` calls each veneer: SHA-256 of the DeviceID public key,
   the paged alias certificate's length, an alias signature over a fixed
   digest verified with micro-ecc against `tfw_dice_alias_pub`, and a
   buffer in Secure SRAM, refused with TFW_ERR_RANGE. `qemu_tz_test.sh`
   asserts each line and that `tz_ns.elf`'s symbols name the four veneers
   and no seed, CDI, UDS or private-key symbol.

Out of scope: GTZC, the H563 console, flashing, TZEN/RDP/option bytes/OTP,
CI workflow changes, a distinct alias key (slice b's `alias_seed` is the
DeviceID seed until the CDI-derived alias lands).
