# 590b: the secure-world DICE service API

Epic #590, ADR `docs/multi-arch/adr-mcu-dice-attestation.md` slice (b):
"The secure-world DICE layer (CDI, DeviceID key, alias key) behind the NSC
API, host-tested." Tenant Agent ruling 935. Slice (a) (`row/590-tz-split`)
builds the TrustZone split and the veneers; this slice is only the service
and its host tests, so the two land in either order. `docs/plans/590.md` is
slice (a)'s; this file is slice (b)'s alone, so the two never conflict.

## Objective

`src/tz/dice_service.{h,c}`: the secure world holds the UDS-derived DeviceID
seed and the CDI; the non-secure world reaches four entry points and nothing
else:

| Call | Returns |
|------|---------|
| `tfw_dice_deviceid_pub(out, cap)` | DeviceID public key, X‖Y, 64 bytes |
| `tfw_dice_alias_pub(out, cap)` | alias public key, X‖Y, 64 bytes |
| `tfw_dice_alias_cert(nonce, off, out, cap, total, got)` | alias certificate bytes from `off`, at most `cap` |
| `tfw_dice_alias_sign(digest, dlen, sig, cap)` | ES256 r‖s over a caller-given 32-byte digest, alias key |

Rules every call keeps:
- no call returns a CDI, a private scalar or a seed; they never leave the
  service's static state, which is zeroed by `tfw_dice_service_clear`;
- every buffer is checked against the caller's size before anything is
  written: a NULL pointer, a short buffer or a wrong digest length is
  `TFW_ERR_LENGTH` (or `TFW_ERR_RANGE` past the certificate's end) and the
  output is untouched;
- the four entry points carry `TFW_NSC` (`cmse_nonsecure_entry` under
  `-mcmse`, nothing on host); every pointer goes through
  `TFW_NS_CHECK(ptr, len)` (`cmse_check_address_range` under `-mcmse`, a
  non-NULL check on host).

Implemented over the existing code, unchanged: the DeviceID key is
`tfw_deviceid_p256_*` over HMAC-SHA256(UDS, `TFW_DEVICEID_LABEL`); the alias
certificate is `tfw_alias_tbs_digest` + `tfw_alias_cert`. The alias key is
today's alias-certificate subject key on the P-256 soft root, which is the
DeviceID key (`src/crypto/soft/id_p256.c`); a CDI-derived alias key is a
later slice and changes only `alias_seed()` in the service.

`tfw_dice_service_init(inputs)` is secure-only (not NSC): secure boot hands
it the UDS, the CDI, the UEID, the firmware measurement and the tier.

## Slices

1. This plan.
2. `src/tz/dice_service.{h,c}` and `test/unit/test_dice_service.c` with its
   `mk/host.mk` rule. Tests: each call equals the current non-secure path
   for a fixed UDS (`tfw_deviceid_p256_public`, `tfw_soft_id_pubkey`,
   `tfw_alias_cert` over `tfw_soft_id_sign`); NULL and short buffers are
   refused and nothing is written; an alias signature verifies under the
   alias public key; no output equals the CDI, the seed or the scalar.

## Out of scope

Linking the service into any image (size-check on mps2-an505 and
nucleo-h563zi stays as main), the veneers and the secure/non-secure link
(slice a), a CDI-derived alias key, board flashing.
