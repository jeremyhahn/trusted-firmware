# 590c: device-attest-01 dice evidence from the secure DICE service

Epic #590, ADR `docs/multi-arch/adr-mcu-dice-attestation.md` slice (c):
"device-attest-01 dice evidence from the H5, checked against go-xkms in a host
test." Tenant Agent ruling 935. Starts from slice (b) (`src/tz/dice_service.{h,c}`,
`docs/plans/590b.md`); this file is slice (c)'s alone.

## The evidence

The attestation object of draft-ietf-acme-device-attest-10, CBOR map:

| Key | Value |
|-----|-------|
| `fmt` | `"dice"` (the name `xkms/avr` `FormatDICE` and go-xkms's device-attest-01 use) |
| `attStmt.x5c` | `[alias certificate, DeviceID certificate]`, leaf first |
| `attStmt.alg` | `-7` (ES256) |
| `attStmt.sig` | ES256 r‖s by the alias key over SHA-256(`authData`) |
| `authData` | the 32-byte challenge nonce |

The nonce is bound as `Device.AttestCert` binds it: it is the alias
certificate's `eat_nonce` (the service's `tfw_dice_cert_page_t.nonce`), and the
alias signature covers it again. The alias certificate carries the UEID and
the firmware measurement (claim 273, FWHash) in its UCCS extension.

The DeviceID certificate is not the service's: the service holds the DeviceID
key and answers its public key; a manufacturer CA (the factory) certifies it.
The host test plays that CA over `tfw_dice_deviceid_pub`.

## Where the bytes come from

The host build of `src/tz/dice_service.c`: `test/unit/test_dice_service.c`
gains a case that runs the service on fixed inputs (UDS, CDI, UEID, FWHash,
nonce) and holds its DeviceID public key, alias certificate and alias
signature over SHA-256(nonce) to `sdk/go/testdata/dice_service_vectors.txt`
(hex, one `name value` line each). `TFW_DICE_VECTORS_WRITE=1` rewrites the
file, so the C side cannot drift from what the Go test reads.

## The Go side (sdk/go/diceevidence.go)

- `DICEAttestationObject(aliasCert, deviceIDCert, nonce, sig)`: assembles the
  object above (deterministic CBOR, the shortest heads).
- `VerifyDICEAttestation(obj, nonce, roots, measurement)`: the checks of
  device-attest-01's dice verifier, standard library only: `fmt` is `dice`;
  `x5c[1]` chains to `roots`; `x5c[0]` is signed by `x5c[1]`'s key (the
  DeviceID key); `eat_nonce` equals the nonce; `sig` verifies under
  `x5c[0]`'s key (the alias key) over SHA-256(`authData`) and `authData` is
  the nonce; FWHash is present and equals `measurement` when one is given.

go-xkms is not imported: sdk/go is Layer 0 and depends on nothing in the
stack (`sdk/go/go.mod`), and go-xkms resolves to over 200 modules. The chain
check mirrors go-xkms's `VerifyAKCertificateChain` (leaf first, each signed
by the next, the last under a root); the nonce and measurement checks mirror
its dice statement's freshness and TCB-info checks.
