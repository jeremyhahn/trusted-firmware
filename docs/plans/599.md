# Plan: SPEC row stm32h5, open follow-ups (Refs #599)

## Objective

Land the guard written with #596 (Refs #566) on `row/599-crypto-tier-guard`,
a fresh branch from main: #596 put
`make firmware BOARD=stm32h573i-dk CRYPTO=stm32h5` in
`.github/workflows/ci.yml`, but the test that keeps a declared tier built in
CI stayed on `row/599-stm32h5` (left as it is, DS-2787). Without it, a tier a
board declares in `ARCH_CRYPTO_TIERS` can lose its CI build again and break
only on the bench, as #566 did. `row/599-stm32h5` (#596 folded, then
main) is merged into this branch (ruling 1143); its copy of the guard is
the first version of slice 1's.

## Slices

1. `scripts/test_ci_crypto_tiers.py` (`make scripts-test`): ci.yml carries a
   `make firmware BOARD=<board> CRYPTO=<tier>` step for every tier a
   `boards/*/profile.mk` declares in `ARCH_CRYPTO_TIERS`. Tests: the DK
   declares `stm32h5`; every declared tier has a step; the scan sees a
   missing step; main's ci.yml with its `CRYPTO=stm32h5` line removed reports
   (stm32h573i-dk, stm32h5) missing. The scan reads only `run:` commands
   (Codex P1, #619): dropping just the run command, or a run command without
   `CRYPTO=` under the same step name, is reported; a `#` comment naming the
   build does not count. Only a real `make firmware` invocation counts
   (Codex round 3 P1, #619): commands are tokenized shell-aware, comments
   stripped, split at `;`/`&&`/`||`/`|`/`&`, and a simple command counts
   when it starts with `make` or `scripts/in-toolchain-image.sh <image>
   make`; an inline `# make firmware ...` or an `echo make firmware ...`
   is reported. `mk/arch/*.mk` is not scanned: ESP32's
   `hmac-p256` belongs to `IMAGE_TARGET` boards, outside firmware-matrix
   (`mk/firmware.mk`), built by esp32-build and not `make firmware`.
2. This plan and the changelog fragment.
3. `docs/boards/stm32h573i-dk.md`: the stale "Hardware crypto: fails ...
   PKA/HASH not ported" bullet agrees with the table row above it (the
   `CRYPTO=stm32h5` tier drives the HASH and PKA, #544, built in CI by #596;
   the default image is the soft tier).

## Row PR #857

The row's one PR (DS-10127): every row lane merges here, past its first
brief (the refused I2C rate). Each folded slice is one line: what it pins,
the source it covers, the test that pins it (its `changelog.d/599-h5-*.md`
fragment in brackets). `src/` is `src/hal/cortex-m/stm32h5/` unless named.

Crypto (PKA, HASH, RNG, provider, sign yield):
- A refused or error-flagged PKA sign wipes d and k: `src/crypto/stm32h5/h5_pka.c`, `test/unit/test_h5_pka.c` [pka-sign-refusal-wipe].
- The provider returns a working PKA's accept and reject and keeps the PKA: `src/crypto/stm32h5/provider.c`, `test/unit/test_h5_pka.c` [provider-pka-answer].
- Each `tfw_crypto_init` re-decides the PKA: `src/crypto/stm32h5/provider.c`, `test/unit/test_h5_pka.c` [pka-provider-reinit].
- Provider init ORs on the HASH, RNG and PKA clocks first: `src/crypto/stm32h5/provider.c`, `test/unit/test_h5_crypto_provider.c` [provider-clock-order].
- The HASH model faults an SR clear while a digest is in flight: `src/crypto/stm32h5/h5_hash.c`, `test/unit/test_h5_hash.c` [hash-clear-after-init].
- RNG init and read error paths: `hal_rng.c`, `test/unit/test_h5_netif.c` [rng-error-stays].
- RNG bring-up when HSI48 never readies: `hal_rng.c`, `test/unit/test_h5_netif.c` [rng-hsi48-timeout].
- The sign yield drains RX before each timer sweep: `hal_eth_sign_yield.c`, `test/unit/test_h5_sign_yield.c` [sign-yield-rx-drain].
