# Plan: row #606, the ESP32-P4 operator session bound to the eFuse UDS

Row `esp32-p4-operator-session` (#606, carries #563). Owner decision 11-20,
queue 248 (d), ruling 1024 (b): "the ESP32-P4 operator session binds to a key
in the P4 eFuse key storage used through the ECDSA or HMAC peripheral, never
readable by software."

## Objective

The `hmac-p256` image on the P4 links the element tier's auth session
(`src/core/auth_session.c`, issue #4) in place of `auth_session_none.c`, so
OTAActivate and OTAConfirm are gated by an operator signature, and the trust
anchor of that session is bound to the `HMAC_UP` UDS key already burned on the
bench P4. No new eFuse key and no burn.

## Design

- The session holds no secret: it verifies an ES256 signature over
  `"tfw-auth-v1" || serial || nonce` with the operator public key from the
  platform block (offset 68). What must be bound is that public key.
- Binding tag: `HMAC-SHA256(UDS, "tfw-opsess-v1" || operator_pubkey)`,
  computed by the HMAC peripheral on the `HMAC_UP` key block. Stored in the
  platform block's reserved span at offset 132 (32 bytes, under the CRC).
- `tfw_crypto_verify_operator` on the hmac-p256 tier (today
  `TFW_ERR_UNSUPPORTED`) recomputes the tag for the key it is given, compares
  it with the stored tag in constant time, and only then verifies the
  signature with micro-ecc. A key rewritten in flash without the device's
  peripheral fails the tag. The computed tag lives on the stack for one call
  and is zeroed. Software never reads the key block: only
  `esp_hmac_calculate` touches it.
- Opt-in per board: `BOARD_FEATURES_ON += AUTH_SESSION` in
  `boards/esp32p4-poe/profile.mk`; the QEMU C3 board keeps the open gate
  (its OTA rows run unsigned).

## Slices

1. Plan, design note (`docs/multi-arch/esp32-p4-design.md` 2.5), failing
   test `test_esp_opsess` (auth_session.c over crypto_hmac_p256.c with the
   faked peripheral): a good signature with a bound key opens the gate; a bad
   signature, an unbound key and a wrong tag do not. Then the provider's
   `verify_operator` and the firmware.mk wiring; `make test`.
2. Provisioning the tag: the provisioning image (`PROVISION=1`,
   `src/hal/esp32/prov_uds.c`) computes the tag through the peripheral and
   `tfwprov --bake` writes it at offset 132. Tests on both sides.
1a. Codex P1 on #607: `tfw_crypto_random` drew the operator nonce with the
   noise source off (ESP-IDF v5.5.5 disables it before the app, no radio
   here). It now takes the ADC unit lock, switches the source on around
   `esp_fill_random` and off after, as `tfw_prov_uds_random` does, and fails
   closed with `TFW_ERR_BUSY` when the lock is held, so AUTH_CHALLENGE is
   refused. Tests: `test_esp_crypto_hmac_p256` (order, busy draws nothing),
   `test_esp_opsess` (busy refuses the challenge; the nonce is drawn with the
   source on). Also the cppcheck variableScope fix in `verify_operator`.
1b. Codex P1 on #607, round 2: the grant outlived its TCP peer, so a host
   that replaced a quiet one or dialled in after a hangup passed the gate
   unsigned. `hal_uart.c` now ends the operator session and any pending
   challenge (`tfw_auth_session_init`) whenever it lets a host go. Tests:
   `test_esp_uart_mutate` (every drop ends it once, a refusal ends nothing),
   `test_esp_wire_auth` (a second host authenticates on its own).
3. `make esp32-build BOARD=esp32p4-poe` (needs ESP-IDF v5.5.5) and the bench
   run of OTAActivate and OTAConfirm (a board lane).

## Out of scope

- Any eFuse burn or a second key (ECDSA_KEY): an owner step (CA 583).
- The ECDSA peripheral path (option (b) of 2.1).
