# Plan: SPEC row device-capabilities follow-ups (#627)

## Objective

The row is shipped, and its "There is no `delay()`" requirement is met, but
nothing enforces it (docs/device-capabilities/engineering.md). This row adds
the gate that enforces it.

## Slices

1. `row/devcaps-no-delay-lint`: `make lint-no-delay`, a grep gate in
   `make lint` (mk/host.mk). It refuses calls to `delay()`, `_delay_ms()`,
   `delayMicroseconds()` and `vTaskDelay()` in the firmware C under `src/`,
   `boot/`, `boards/` and `include/` (the vendored `third_party` is not
   swept). A comment line that names the rule ("there is no delay()") does
   not count. `_delay_us()` and `tfw_hal_delay_us()` are allowed: they are the
   bus bit-banging delays of the HAL, measured in microseconds, and no
   command handler waits on them. It prints findings as `path:line: no-delay`
   and never prints the matched text, like the other grep gates.
   Tests: `lint-grep-selftest` plants one call of each refused name, which
   must fail the gate with `path:line: ` and without the planted text. It
   also adds negative cases that must pass: a `_delay_us` call, a
   `tfw_hal_delay_us` call and a comment that names `delay()`.
   The engineering.md row moves from "met, not enforced" to "met, enforced".

## Out of scope

- Test code and mocks (`test/`): the host test harness may model a delay.
- Go and Python sleeps, which `lint-test-sleep` already covers.
