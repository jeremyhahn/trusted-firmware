# Plan: #627 device-capabilities open follow-ups

## Objective

`tfw_sched_poll()` in src/caps/sched.c clears a timer slot when its deadline
passes whatever the HAL answered to the revert write. A refused revert leaves
the pin at its held level with no timer left to drive it back, the one thing
the scheduler exists to prevent. TIMER_CANCEL already keeps the slot when its
final-level write fails; the sweep should do the same.

## Slices

1. Sweep retries a refused revert.
   - Test first (test/unit/test_sched.c):
     `test_a_revert_the_hal_refuses_keeps_the_timer_and_the_next_sweep_retries`
     -- the mock refuses the gpio write at the deadline; the pin stays held,
     the timer stays active (TIMER_QUERY: active 1, held 1, remaining 0);
     once the HAL accepts, the next sweep reverts the pin and frees the slot.
   - Fix: `tfw_sched_poll()` clears the slot only when the write succeeded or
     the pin no longer resolves.
   - changelog.d/627-sched-poll-revert-fault.md, one `### Fixed` line.

## Out of scope

- Mock changes (`tfw_mock_gpio_io_fails` already exists).
- SPEC, ADR and docs text.
- Other #627 follow-ups.

## Merged #751: #627: api.md states the zero-length EEPROM_READ and EEPROM_WRITE replies

Objective: `docs/device-capabilities/api.md` bounds `len` by
`TFW_EEPROM_CHUNK` but says nothing about zero. On main a zero-length
`EEPROM_READ` answers `TFW_OK` with an empty `data`, while an `EEPROM_WRITE`
with no `data` is refused at dispatch with `TFW_ERR_BAD_ARGC`. Document the
code as it is (r109, non-architecture); the handler is not changed.

## Slices

1. `docs(caps)`: one paragraph in api.md's EEPROM section, after the bounds
   paragraph: a `len` 0 read is `TFW_OK` with an empty `data`; `addr` is
   still checked (`TFW_ERR_RANGE` at or past `TFW_EEPROM_SIZE`,
   `src/caps/storage.c` `tfw_storage_cmd_read`), and an `addr` below
   `TFW_EEPROM_RESERVED_END` still passes `tfw_auth_gate` (`boot_owned`); a
   2-byte write is below the 3-byte minimum (`src/core/commands.def`) and is
   `TFW_ERR_BAD_ARGC` (`test/unit/test_storage.c`
   `test_a_zero_length_write_is_refused`). No new test: the write is pinned
   by that test, the read by `test/unit/test_storage_mutate.c`. Changelog
   fragment `changelog.d/627-eeprom-read-zero.md`.
2. Fold PR #630 (`row/devcaps-no-delay-lint`, merged): `make lint-no-delay`

3. Fold PR #731 (`row/devcaps-cli-user`, merged): `docs/device-capabilities/`
