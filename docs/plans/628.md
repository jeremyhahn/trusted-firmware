# Row cortex-m (#628): open follow-ups

## Objective

docs/cortex-m/engineering.md's "tfw-boot enables no interrupt: its UART
polls" is pinned end to end only, in QEMU. Pin it on the host too: a test of
boot/hal/cortex-m/mps2/boot_uart.c over a register model, as the RP2350's
boot UART has (boot/hal/cortex-m/rp2350/test/).

## Slices

1. row/mps2-boot-uart-test (this slice).
   - `boot/hal/cortex-m/mps2/test/test_boot_mps2_uart.c`, built once under
     each MPS2 profile (an500: UART0 at 0x40004000, 25 MHz; an505: UART0 at
     0x40200000, 20 MHz) by `make boot-test`.
   - The model holds UART0's five registers and nothing else: any other
     address fails the test, so the file touches no NVIC, SCB or timer.
   - The model checks CTRL's interrupt enables (TXINT, RXINT, TXOVRINT,
     RXOVRINT) on every register access, so an enable written and cleared
     again between two accesses still fails.
   - Tests: init at 115200 (divisor, overrun clear, TX and RX enabled, no
     interrupt enable); TX writes DATA after TXFULL clears; RX reads DATA
     only when RXFULL is set; the hand-over drains TXFULL, then CTRL and
     BAUDDIV to 0, the overrun and interrupt flags cleared.
   - Refusals: baud 0; a divisor under BAUDDIV_MIN (16), with the edge at
     exactly 16 accepted; TX on a UART never enabled writes nothing and does
     not wait; RX with RXFULL clear leaves the byte alone; the hand-over of a
     UART never enabled does not wait on TXFULL.
   - docs/cortex-m/engineering.md names the host test beside the QEMU one.

2. row/mps2-bus-regs-test.
   - test_mps2_bus, test_mps2_spi_row and test_mps2_optiga link the image's
     sbcon.c and pl022.c instead of re-defining the seven accessors. The
     accessors' TFW_CM_REG goes to test/model/mps2_bus_model.c through
     test/model/cortex-m/mps2/cm_regs.h; the model decodes the address
     against mps2-an505's bases and hands the access to the suite's bus,
     whose old accessor bodies become the tfw_mps2_model_* hooks.
   - A host pointer cannot tell a read from a write, so the link wraps each
     accessor (-Wl,--wrap): the wrap gives the direction, and the model fails
     an accessor that makes no access, more than one, or one at a register
     that direction does not allow, and any access outside an accessor.
   - test_mps2_adc: the image's hal_adc.c under mps2-an505's profile with
     the model linked and every hook failing; init OK, set_ref unsupported
     for each reference, every channel 0..255 refused with the word left.
   - Proof: swapping CONTROLS/CONTROLC fails test_mps2_bus and
     test_mps2_optiga; flipping a PL022 offset fails test_mps2_bus and
     test_mps2_spi_row.

## Out of scope

- The application's UART (src/hal/cortex-m/mps2/hal_uart.c) and its
  interrupt path: it has its own tests.
- A shared home for the register-layer stand-in: the test takes the RP2350
  test's cm_regs.h, which names no SoC.

## Slice 3: boot_hal_cortex-m.c on the host (row/cm-boot-hal-test)

- The jump to the application (barriers, MSP write) moved to boot/hal/cortex-m/boot_jump.c, listed in ARCH_BOOT_SRCS (mk/arch/cortex-m.mk); the rest of boot_hal_cortex-m.c builds on the host.
- boot/hal/cortex-m/test/test_boot_hal_cortex-m.c (mk/boot.mk, built under mps2-an505 and mps2-an500): page size, page writes inside/below/past the region and unaligned, nvm block range, handoff round trip, factory copies before the reset cause, reset, watchdog.
- Fix: tfw_boot_flash_write_page compared addr + page > end, which wraps for the last page of the address space; it now compares addr > end - page, with a static assert that the region holds a page. The wrap test failed before the fix.
- Not run here: make integration-test-cortex-m (no arm-none-eabi-gcc on this node); the QEMU boot tests are what exercise boot_jump.c.
