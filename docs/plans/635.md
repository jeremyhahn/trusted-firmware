# 635: application-sdk open follow-ups

Row `application-sdk` (docs/SPEC.md), issue #635.

## Objective

Close the row's open follow-ups, each with the test that proves it.

## Slices

1. row/app-symbols-test (shipped in #636, main f46e1c3f; main's version of
   the test is the one kept): `scripts/app_symbols.py` (the symbol reader of
   app-firmware-check, mk/app.mk) gains `scripts/test_app_symbols.py`, run by
   `make scripts-test`. It pins:
   - a symbol defined in an allocated section is printed, exit 0;
   - a gc-dropped symbol (absent from the image, or left in a section the
     image does not load, or undefined) is not, exit 1;
   - a compiler suffix (`tfw_app_init.lto_priv.0`) matches `tfw_app_init`,
     while a longer name (`tfw_app_init_extra`) does not;
   - a non-ELF file is refused, exit 2, and a wrong argument count is usage,
     exit 2;
   - ELF32 little-endian and ELF64 big-endian images both read.
   The images are built byte by byte in the test (no toolchain needed); one
   more case links a real host image with `gcc -ffunction-sections
   -Wl,--gc-sections` and is skipped where no gcc is installed.

## Out of scope

- Changes to app_symbols.py's behaviour or to mk/app.mk.
- The row's other slices (device onboarding, wire commands, pin ADRs),
  which wait on their owners as docs/plans/461.md records.
