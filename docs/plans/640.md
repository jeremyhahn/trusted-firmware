# #640: SPEC row boards, open follow-ups

## Objective

Close the unchecked items of row issue #640. The one open item is
row/476-toolchain-tag-race (#476): `make docker-build-toolchain` runs its
`cat /etc/ci-toolchain.txt` check on the build-id tag
`$(TOOLCHAIN_IMAGE)-$(IMAGE_BUILD_ID)` before it removes that tag. It no longer
checks the shared class tag after the removal, because another CI leg or a
prune on the shared daemon can remove the class tag in between (PR #471's
Security job). The work is refreshed onto main from the head of closed PR #478.

## Slices

1. Recipe fix (mk/docker.mk): move the check onto the build-id tag, ahead of
   `image rm`; changelog.d/476-toolchain-tag-race.md.
2. Regression coverage (Codex P1 on #478):
   - scripts/test_docker_tag_stub.sh records each call. Its `run` fails on
     the class tag, and on a build-id tag that an earlier `image rm` or `rmi`
     removed.
   - scripts/test_docker_tag.py (DockerTagRace): from the recorded calls,
     the toolchain rule runs only the build-id tag, and runs it before that
     tag's removal. No rule runs the class tag or a removed tag.
   - Mutation proof: the old class-tag check after the removal fails the
     suite; so does a build-id check after the removal.
   - Gate: `make scripts-test`.

docker-build-esp32 and docker-build-optee run no check, so there is nothing
to reorder. The no-class-tag/no-removed-tag test covers them as well.

## Out of scope

The docker-build-it recipe, any .github workflow, docs/SPEC.md, build/.
